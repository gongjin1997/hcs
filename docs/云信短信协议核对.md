# 云信短信协议核对

本核对仅使用本地提供的材料，未向外部站点上传文档、地址或凭据，未调用真实短信网关。

## 材料与范围

- `logs/pdf/云信网关HTTP3.0协议接入用户手册.pdf`：18 页；封面版本记录为 V0.1，日期为 2021-11-18。本说明按 PDF 实际页序引用。
- `logs/pdf/云信通短信平台接入指引.docx`：应用申请、网络策略、安全网关接入和短信内容报备指引。
- 本次适配器仅实现 §4.1 `HttpSmsBatchSend`，不实现 §4.2 一对一发送、上行接收、状态回执回调或主动轮询。

完整发送地址由短信管理员确认并按租户配置，不从协议样例推断生产地址，不提供公共网关默认值。本说明不复制指引中的内部地址、人员联系信息或账号凭据。

| 项目 | 本地依据 | 实现约定 |
| --- | --- | --- |
| 传输 | PDF §3、§4.1，第 2-3 页 | 单次 HTTP/HTTPS POST；完整地址原样使用，不自动拼接路径 |

## 响应与示例差异

PDF 第 4 页字段表把 `code` 标为 Integer，第 5 页样例把根 `code` 写为字符串 `"0"`。同时兼容表内整数编码及对应的数字字符串，拒绝布尔值、浮点数、空值、未知编码和任意消息文本作为编码。第 5 页样例缺少部分 JSON 引号/分隔符，只据其字段含义做兼容，不宽松接受非法 JSON。

根 `code=0` 仅表明批请求通过入口处理，必须逐条检查 `data[].code`。必须收到请求中每个号码的唯一明细；缺行、重复号码、多余号码、号码类型不正确、缺少/无效结果码、非法 JSON 均按“受理状态未确认”处理，整次解析不返回部分成功。响应顺序不必与请求一致，结果按请求顺序返回。

根 `code` 非零时，按该根编码返回本批全部号码 `accepted=false`，不把明细当作已受理。`message` 是不可信网关文本，不进入结果、错误、日志或审计。

第 4 页表声明成功时返回 Long 类型 `msgId`，但第 5 页示例省略该字段。因此 `message_id` 允许缺省；收到整数或非空字符串时保留为字符串，避免大整数精度损失，拒绝布尔及其它类型。不以 `msgId` 缺省推断失败，也不以存在 `msgId` 推断送达。

## 状态码与投递边界

PDF §5.3，第 18 页列出以下编码：

| 编码 | 含义 |
| --- | --- |
| 0 | 处理成功，即此接口受理成功 |
| 2 / 11 | 用户名或密码错误 / 签名错误 |
| 4 / 6 / 7 | 账号停用 / 账号过期 / 余额不足 |
| 9 / 10 | 数据结构错误 / 时间戳无效 |
| 30 / 31 / 32 / 34 | 请求频繁 / 内容超长 / 手机号码格式错误 / 号码个数过多 |
| 41 / 42 / 44 | 内容为空 / 参数格式错误 / 报备 IP 与实际来源不匹配 |
| 45 / 46 / 47 / 48 | 扩展端口错误 / 模板错误 / 扩展端口过长 / 模板参数过长 |
| 99 | 其它错误 |

根或单号码结果出现 2、11，应由投递工作进程阻断该租户当前配置修订的后续发送，等待管理员修正配置，不能继续密集尝试。PDF 第 6、16-17 页另有认证失败次数触发短期锁定的说明，因此适配器不自动重试。

`accepted=true` 只表示网关受理，不表示手机收到。PDF §4.3-§4.4 的状态报告是独立流程：第 9、12 页字段表以 `status=7` 表示成功，但第 9-10 页推送样例把成功报告写成 `status="0"`，存在材料矛盾。首期不实现回执，不从发送响应编造 `DELIVERED` 状态；后续接入回执前需短信管理员确认状态规则、鉴权和防重放方案。

## 超时、安全与重发规则

- `SmsGatewayError` 只公开固定 `reason_code` 与 `uncertain`，不保存或转发原始 HTTP 异常、响应正文、地址、口令或签名。结果对象的默认 `repr` 也不展示手机号、消息 ID 或短信正文。
- HTTP 401/403 返回 `AUTH`、`uncertain=false`；明确连接失败返回 `CONNECT`、`uncertain=false`。所有超时按 `TIMEOUT`、`uncertain=true` 处理；写入、读取、协议异常、其它 HTTP 异常及无效响应均保持未确认，不能据此认定未发送。
- 请求只有一次，没有 SDK 重试循环。协议仅承诺在回执中带回 `smsBatchId`，未声明它是去重或幂等键；不得因批次号相同就认定重复提交不会多发。
- 自建 `httpx.Client` 默认 TLS 校验开启，禁用环境代理、环境证书覆盖和重定向。显式关闭 TLS 校验只由管理员配置决定。完整地址不能携带 userinfo 或 fragment。
- 注入的客户端由调用方负责 TLS、代理和底层重试策略；`verify_tls` 仅用于本模块自建客户端。适配器不关闭注入客户端，但仍在每次请求显式设置超时并禁止重定向。

## 接入申请及业务策略

DOCX §1 要求完成应用申请，§2 要求根据系统是否具备公网业务申请对应网络及安全网关策略；通过代理接入时，对外服务地址由短信平台管理员提供。不得根据说明中的网络拓扑私自选用地址或通过环境代理绕过审批。

DOCX §4 及附表明确：短信中包含访问链接或联系电话，需要单独报备，并建议尽量避免。默认升级短信模板应只含必要的租户、告警标识、级别和简短摘要，不自动加入平台链接、联系人电话或其它未报备内容。传输层保留通用 `content`，不替代业务模板审批。

业务总开关默认关闭；每租户独立配置和开关。仅升级短信选择统一目录中当前启用、允许通知、租户范围匹配且有有效电话的既有用户。入队和发送前均须复核，不新建人员、不使用历史联系人快照作为授权来源。这些属于配置/API/工作进程责任，适配器本身不会启动发送任务或读取业务配置。
