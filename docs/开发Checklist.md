## 0. 准备：租户、账号、网络与环境

- [ ] 确认两个租户的纳管范围：每个租户的区域、项目（Project ID）、DataArts Studio 工作空间清单
- [ ] 为每个租户确定接入方式：IAM 账号密码（换 Token）或 AK/SK（签名）；申请只读 IAM 用户或只读 AK/SK，按下表开通各服务的只读权限（策略名称以局点 IAM 为准）
- [ ] 确认每个租户的局点是否部署了云监控 CES：ManageOne 运营面「服务列表」里是否有“云监控”；或 IAM `GET /v3/auth/catalog` 中是否有 type 为 `metric` / `ces` 的服务；最简单是保存租户后点「连通性测试」，平台自动探测
- [ ] 没有 CES 的租户：确认是否有可用的 Prometheus（node\_exporter）及访问地址；都没有则接受“只巡检状态，不判断 CPU / 内存 / 磁盘”
- [ ] 确认 CCE 集群 K8s API 的访问方式：经 CCE 网关用 Token / AK/SK 访问（需局点支持），否则准备只读 kubeconfig（ServiceAccount，pods / events / namespaces 的 get、list）
- [ ] 按 HCS 8.5.1 核对各服务的 Endpoint 和 API 版本，填写全局模板 `INSPECTOR_HCS_ENDPOINTS`（默认 `{service}.{region}.{domain}`）；局点差异在租户的「服务 Endpoint 覆盖」里填
- [ ] 开通网络：巡检服务器 → 各租户 IAM 和服务 Endpoint（HTTPS 443）、→ CCE 集群 API、→ Prometheus（如有）、→ SMTP 网关；运维办公网 → 控制台
- [ ] HCS API 网关使用自签证书时，准备内部 CA 证书
- [ ] 申请 SMTP 发件账号和发件地址，确认值班收件组、报表收件组和各租户的报表收件人
- [ ] 准备运行环境：一台虚拟机（建议 4 核 8 GB、100 GB 数据盘，Docker 20.10+ 和 compose v2）；PostgreSQL 16、Redis 7 随 compose 一起部署（见 `docs/部署运维手册.md` 第 2 章）

- [x] 本地开发环境：`make init` → `make dev-mock` / `make dev-api` / `make dev-web`，不需要 Docker

## 1. 基础框架、登录与权限

- [x] 前后端 monorepo，`Makefile` 统一命令入口，`.env.example` 列出全部配置
- [x] 统一响应信封 `{code, message, data}` 和业务错误码；`X-Request-ID` 贯穿请求和日志
- [x] 平台登录只用用户名 + 密码（PBKDF2-SHA256，20 万次迭代），Token 默认 12 小时有效；AK/SK 只用于平台调用 HCS，不用于登录
- [x] 勾选“7 天内免登录”后 Token 有效 7 天；登录页记住上次使用的账号
- [x] 连续输错 5 次密码锁定 10 分钟（`INSPECTOR_LOGIN_MAX_FAILURES` / `INSPECTOR_LOGIN_LOCK_MINUTES`）
- [x] 28 个权限点（8 个模块，按“模块:动作”编码；v0.4 新增 `silence:manage`、`report:config`、`notify:manage`、`task:edit`、`collect:manage`、`setting:manage`，升级时迁移自动授予内置角色），前后端同一套：后端 `require_perm(...)`，前端路由 `meta.perm` + `v-perm` 指令；越权返回 40301
- [x] 4 个内置角色（平台管理员 / 运维负责人 / 值班运维 / 只读访客）+ 自定义角色；「角色与权限」页按模块勾选权限点
- [x] 数据范围：用户可限定为部分租户；顶栏「租户切换」通过请求头 `X-Tenant-Id` 传给后端，与用户范围取交集，越权访问返回 403
- [x] 用户管理：新增、编辑（角色、数据范围）、启停、重置密码（同时解除锁定）；不能停用自己，也不能取消自己的管理员权限
- [x] 停用账号后已签发的 Token 立即失效；角色和数据范围每次请求查库，调整后立即生效
- [x] 用户自助修改密码（顶栏头像菜单）
- [x] 操作审计：登录（含失败）、告警处置、静默、台账维护 / 同步 / 导出 / 导入、容器事件采集与探针、报表、规则、任务执行与编辑、采集开关、系统设置、通知维护、租户 / 用户 / 角色变更写入 `audit_log`；「操作审计」页按操作类型、关键字、结果、时间（最近 24 小时 ~ 180 天）查询；密码、SK 等敏感字段不入审计
- [x] 首次部署由 `bootstrap` 创建 4 个内置角色和 admin（`INSPECTOR_INIT_ADMIN_PASSWORD`）；`INSPECTOR_ENV=prod` 时不写演示数据，登录页也不显示任何演示账号提示（`/auth/login-options` 只返回版本号）
- [x] 生产密钥：`make gen-env` 随机生成 JWT 密钥、邮件链接密钥、凭据主密钥 `INSPECTOR_MASTER_KEY` 和数据库 / Redis 口令；`INSPECTOR_ENV=prod` 时 JWT 密钥为默认值或短于 32 字节、邮件链接密钥短于 16 字节、未设置主密钥、使用 SQLite 都会拒绝启动
- [ ] 给运维组成员开通账号，分配角色和数据范围；admin 初始口令改掉后，清空 `deploy/.env` 里的 `INSPECTOR_INIT_ADMIN_PASSWORD`
- [ ] 和运维组确认内置角色的权限划分（例如值班运维是否允许发送报表、执行任务）
- [x] 审计日志保留期：「系统设置 → 数据保留」配置（默认 180 天，最少 90 天），`data_cleanup` 每天按保留期清理（具体天数在第 11 节定稿）
- [x] 访问来源白名单：nginx `snippets/allowlist.conf` 只允许运维办公网访问（默认全部放行，部署时填写网段）；`/metrics` 默认拒绝、单独白名单（实测见第 9 节）
