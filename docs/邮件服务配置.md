# 邮件服务配置

入口：通知管理 → 邮件服务。保存后由 API、通知进程和报表发信动态读取，无需修改 `.env` 或重启。

## SMTP 发信

| 场景 | 端口示例 | 加密方式 | 认证 |
| --- | --- | --- | --- |
| 获批的内网白名单中继 | 25 | 按中继要求选择 NONE 或 STARTTLS | 白名单中继可关闭 |
| 外部 SMTP 提交 | 587 | 通常 STARTTLS，以服务商配置为准 | 按服务商要求 |
| 建连即 TLS | 465 | SSL / TLS | 按服务商要求 |

1. 填服务器主机名或 IP，不带 `smtp://` 等协议前缀；设置实际端口。
2. 选择服务器支持的加密方式；需要认证时填写账号和密码/授权码，设置发件地址与可选回复地址。
3. 保存后点击“测试 SMTP 连接（不发信）”检查网络、握手及可选认证。
4. 需要验证投递时填写测试收件人，再明确点击“发送测试邮件”。连接成功不等于中继允许向任意地址投递。

25 端口属于 SMTP，不属于 IMAP。端口不是加密开关，不能仅换端口而保持错误的 TLS 模式。外网发信还需核对出口策略、服务器证书、发件域与中继授权。

## IMAP 连接

IMAP 用于连接收件服务，不能代替 SMTP 发送通知。常见端口为 143（明文或 STARTTLS）和 993（建连即 TLS）。

启用后填写服务器、端口、加密方式、账号和密码，保存后可测试连接与认证。当前检查执行 LOGIN、NOOP、LOGOUT，不获取、标记、移动或删除邮件，也不自动执行邮件回复中的指令。

## 密码与权限

- 密码用平台加密服务保存到数据库，接口只返回“是否设置”。密码输入留空表示保留；明确勾选清除并保存后才移除。
- 首次保存前兼容原部署默认值；首次保存将有效邮件配置完整存入数据库，此后不依赖邮件环境变量。部署主加密密钥仍由原有部署机制管理。
- 修改和连接/发信测试需要通知管理权限及全部租户的数据范围；受限租户用户只读。
- 操作审计记录配置变更与测试结果，不记录明文密码。重启后应保持加密主密钥一致。
