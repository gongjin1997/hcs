## 五个视图不是互斥类别

| 视图 | 对象与统计单位 | 不能据此推断 |
|---|---|---|
| DGC 作业 | DataArts 数据开发（DLF）编排定义，实时和批处理父作业 | 不等于所有引擎上的执行次数 |
| 实时作业 | 定义的 `jobType/processType=REAL_TIME` | 不代表全部实时引擎任务，也不等于全部 Flink |
| 批作业 | 定义的 `jobType/processType=BATCH`，关联本窗口最新实例 | 调度状态不等于执行结果；没有近期实例不等于没有定义 |
| Flink 作业 | 接口明确提供 Flink 引擎/单任务/节点类型的对象 | 不按名称猜测，不将 Flink 一律认作实时；不同对象层级不得混合相加 |
| MRS 作业 | 集群内的原生执行，按 `cluster_id/job_id` 区分 | DataArts 编排节点不等于原生执行；无关联ID时不能按名称去重或认定同一次执行 |

DGC节点作为独立类型 `dgc_mrs_node` 保存。编排节点、父作业和原生执行分别展示来源，五个视图总数不能相加。

## 只读接口链

DataArts V1 使用项目ID及 `dayu-dlf` 服务端点。`workspace` 是请求头中的工作空间ID；省略时仅查询 default，而非全部工作空间。

| 对象 | 方法与路径 | 参数和响应 |
|---|---|---|
| 实时/批作业清单 | GET `/v1/{project_id}/jobs` | 显式 `jobType=REAL_TIME` 或 `BATCH`；`offset` 从0按页，`limit=100`；读取 `total/jobs` |
| 实时运行状态 | GET `/v1/{project_id}/jobs/{job_name}/status` | 列表后先筛选指定作业，仅查询范围内名称；读取 `status/nodes`，保留缺失状态 |
| 定义元数据 | GET `/v1/{project_id}/jobs/{job_name}` | `processType/singleNodeJobType/nodes[].type`；FlinkSQL、FlinkJar、MRSFlinkJob 是引擎证据；混合编排保留多个引擎 |
| 运行实例 | GET `/v1/{project_id}/jobs/instances/detail` | 毫秒 `minPlanTime/maxPlanTime`，窗口固定24小时（接口上限3天）；从0按页；不向此接口发送未定义的 jobType |
| 编排节点执行 | GET `/v1/{project_id}/jobs/{job_name}/instances/{instance_id}` | 小写节点状态及节点起止时间；MRSSpark、MapReduce、MRSFlinkJob、MRSHetuEngine，以及文档描述的 HiveSQL、SparkSQL |
| MRS集群 | GET `/v1.1/{project_id}/cluster_infos` | `currentPage/pageSize`；读取 `clusterTotal/clusters` |
| MRS原生执行 | GET `/v2/{project_id}/clusters/{cluster_id}/job-executions` | 读取 `total_record/job_list`、job_id、job_state、job_result；使用独立分页规则，不套用DataArts页号或节点状态 |

PDF依据：DataArts §5.3.3、§5.3.4、§5.3.15–5.3.17，实体页314–370附近；单任务类型为实体页320，Hive/Spark SQL节点属性为实体页328。

MRS V2的证据边界：上传的8.5.1 MRS PDF没有完整收录此接口；恢复依据是本局点既有成功采集和保留的兼容适配。公有云参考只能辅助解释字段，不能代替局点版本验证。`elapsed_time` 单位未确认时保留原值，不猜换算；可用的起止毫秒时间独立计算时长。

## 状态、实例和范围

- DGC实时 `NORMAL/EXCEPTION/STARTING/STOPPING/STOPPED` 与批实例 `success/fail/running/...` 分别解释。
- 批定义的 `SCHEDULING/STOPPED/PAUSED` 是调度状态。最新实例状态缺失时保留空值，不把调度中当执行成功。
- MRS `job_state` 与 `job_result` 分开保存。FINISHED不能独自证明成功；未知结果不自动恢复告警。
- 实例列表中未匹配批定义的实时子作业/其他实例单独标记为 INSTANCE，不计入批定义总数。
- 采集范围按租户、项目、工作空间和作业标识限定；实时作业在状态和定义详情请求之前过滤。明确的指定模式空列表表示不监控，不回退全量。
- 新环境仍默认关闭采集；修改范围不启动云端任务。原有采集范围与用户规则必须保留，不能在迁移时扩大授权范围。

## 后续日志怎么判断

`job_collection_page`：服务、阶段、workspace及explicit/default模式、页号、页大小、响应总数、当前页条数、实例窗口。不会输出凭据或完整响应。

`job_collection_summary`：定义数、范围内定义数、实例数、未匹配定义的实例数及原因。需要区分：

- `DEFAULT_WORKSPACE_EMPTY`：未显式配置workspace，默认空间为空；先核对实际作业所在空间。
- `EMPTY_DEFINITIONS`：本次定义查询返回空。
- `SCOPE_FILTERED/WORKSPACE_EXCLUDED`：被已配置范围排除。
- `NO_RECENT_INSTANCES`：有作业定义，但窗口内没有实例。
- `LIST_FAILED/INSTANCE_QUERY_FAILED`：查询失败，不应当作正常零任务。

旧迁移已经删除的执行历史无法凭日志恢复；恢复原生查询后重新采集，不构造历史执行记录。

## 指定监控作业

系统管理 → 巡检任务 → DataArts 实时/批作业行的“监控作业” → 选择租户、项目、工作空间 → 查询云端作业 → 仅监控指定作业 → 勾选并保存。名单跨页保留，按精确名称匹配，不把通配符当作选择扩展。

选择“指定作业”但名单为空时，该工作空间不发列表、状态或定义详情查询；未配置的其他工作空间仍沿用原通用范围。已选名单与通用范围取交集，清空通用规则不会扩大一个显式空名单。保存后同步资源的范围标记；在途采集遇到名单版本变化时丢弃未提交结果。

新增本地接口：GET `/system/job-selections/targets`、GET/PUT `/system/job-selections/{tenant_id}/{resource_type}`、GET `/system/job-selections/{tenant_id}/{resource_type}/jobs`。云端发现只调用作业列表，不查询运行状态；所有保存只写本平台配置。

## 更新注意事项

这份 2026-11-09 记录中的 0022 是当时发布的 DataArts/MRS 迁移。2026-11-10 执行队列与恢复改动另加 0023；当前更新包复用既有镜像，仍使用 `bash deploy.sh update /path/to/package.tar.gz`，目标机只需要 docker 与独立 docker-compose。正式环境开关沿用原值；新正式环境仍默认关闭采集。执行和恢复方式见[巡检任务执行与恢复](巡检任务执行与恢复_20261110.md)。

2026-11-10 起，MRS 原生查询默认 `active_and_recent`：分别查询 NEW/NEW_SAVING/SUBMITTED/ACCEPTED/RUNNING（均不带提交时间限制），再并集近24h提交的执行，按 `cluster_id/job_id` 去重，保留长期运行的Flink。旧节点任务的 `window_hours` 不会成为原生过滤条件；`submitted_window_hours` 只调整近期分支。显式 `active_only/recent_only/all_history` 与整轮共享页/条/调用预算详见 [MRS有界采集与参数契约_20261110](MRS有界采集与参数契约_20261110.md)。筛选/分页矛盾或超预算报告覆盖不可确认，不回退全历史。
