# CCE 事件计数与告警处理（2026-11-06）

## 原因

旧实现把下列数据精度问题加入 `RunContext.errors`，流水线因此将任务标记为 `PARTIAL`，平台监测累计至阈值后产生 `R-PLAT-001`“任务连续失败”。这些信息不等同于容器故障。

| 原提示 | 触发条件 | 本次处理 |
| --- | --- | --- |
| Kubernetes 事件次数或时间范围无效 | 次数不是正整数；首次时间晚于末次时间；末次时间超出采样时刻及 20 秒容差 | 跳过无效输入，按具体原因记录 INFO 诊断，不记任务失败 |
| 容器事件累计次数跨越统计窗口 | 事件累计区间跨过最近 10 分钟、1 小时或 24 小时的起点，无法知道其中多少次在窗口内 | 保留原始累计事件和已经记录的增量区间，当前窗口精确值保持未知，仅记录 INFO |
| 事件时间缺失、同 UID 次数或时间倒退 | 缺少可用时间，或再次获取的记录早于本地已采集证据 | 不用当前时间、零值或倒退值覆盖既有记录，仅记录 INFO |

例如某事件从两天前到现在累计 100 次，并不能说明最近一小时发生了 100 次。系统不会猜测分布，也不会因无法精确计数而发平台告警。已知容器故障不会因为计数未知被自动恢复。

此外修正原生 Event 新旧字段兼容：`eventTime` 表示首次观察时刻；存在 `series` 时使用 `series.count` 与 `series.lastObservedTime`。具有有效 `eventTime`、没有 `series` 的单次事件，其未使用的旧 `count` 可以为 0/null，不再将它误判成无效事件。无有效 `eventTime` 的旧事件仍验证正整数次数；无效或不完整的序列不会退回旧字段拼接结果。

## 行为与日志

- 只有上述计数诊断时，采集任务为 `SUCCESS`，`error_summary` 为空，不产生平台失败告警或由此引出的通知。
- 未知计数不进入相关阈值规则，界面/报表仍可显示未知，不伪装成零次或全量巡检正常。
- 真实 CrashLoop、OOM、频繁重启、驱逐仍由原规则判断；认证失败、API 访问失败、分页不完整等仍保留采集失败及平台告警。
- 已有同租户、同项目的任务失败告警，在下一次真正成功的采集后按原平台恢复流程处理。历史失败记录不删除；若同时存在真正的接口错误，任务仍非成功，不会强行关闭告警。
- 诊断日志事件名 `collection_data_unavailable`，级别 INFO；只输出固定原因、计数、租户/项目以及运行上下文，不输出上游事件正文。

| `phase` | `reason` | 含义 |
| --- | --- | --- |
| event_validation | event_count_invalid | 次数无效 |
| event_validation | event_time_missing | 缺少可用的首次/末次时间 |
| event_validation | event_time_reversed | 首次时间晚于末次时间 |
| event_validation | event_time_future | 末次时间超出采样时刻容差 |
| event_validation | event_counter_regressed / event_time_regressed | 同 UID 计数或时间倒退 |
| event_window_count | cumulative_count_crosses_window | 累计区间无法精确归入统计窗口 |

`stats.event_data_diagnostics` 保存各校验原因的输入事件数；`event_window_unknown_checks` / `event_window_unknown_events` 保存计数检查和相关事件条目数。它们用于排查，不参与告警判定。
