# 监控系统对比与优化

核对日期：2026-11-05。参考公开官方资料，优化现有 HCS-Inspector；未连接或修改正式云环境。

## 比较结果

| 参照 | 值得采用的做法 | 本系统的处理 | 不照搬的部分 |
| --- | --- | --- | --- |
| HCS / ManageOne 运维白皮书 | 以统一资源身份关联监控、告警和运维信息，支持同一对象逐层查看。[S01] | 台账、告警及三个资源监控页面使用同一本地主键、明确租户和公共链接规则。 | 不新增 CMDB 平台，不加入云端自动修复或资源变更。 |
| CES 资源分组与告警详情 | 按业务组织资源，从告警查看资源与状态变化。[S05][S06] | 保留本地业务分类；资源监控、作业、告警分别成为完整工作区，相关页面保留原权限。 | 不用业务分组替代租户授权，不调用云端建组接口。 |
| 官方 Exporter / Grafana 方案 | 统一资源选择条件；区分指标上报、缓存和原始时间；导出明确范围与聚合。[S07][S08][S09] | 显式租户请求头、实例直达、同查询范围 XLSX；巡检覆盖与指标采样分别表达。 | 不安装新 Exporter/Grafana，不将公有云 CES 指标当成当前 HCS 原生接口。 |
| CloudScope 告警文档 | 用区域、上报组件、节点定位故障对象。[S04] | 既有资源、项目、子对象和通知结果在告警详情中关联查看。 | 查到的实际正文对应 HCS 8.6.1，不能证明 8.5.1 接口可用。 |
| Zabbix 官方华为集成 | 已核实网络设备和 OceanStor 模板；本轮检查的官方云模板目录中未发现 HCS API 模板。[S11][S12] | 不增加额外部署。 | 不据此断言所有社区或历史集成均不存在。 |

## 本轮收拢的结构

- **入口**：14 个一级菜单收拢为 9 个。资源监控包含覆盖、ECS、DCS、GaussDB；告警包含事件、规则、通知、维护与静默；作业共用一套页内导航。旧地址保留。
- **公共定义**：菜单、页内导航、路由标题和权限复用工作区定义；资源链接复用本地主键与租户校验；各服务请求复用显式租户头。服务原生 API 的单位、分页和时间仍各自按合同处理。
- **监控覆盖**：只读汇总既有开关、任务、项目和巡检证据。区分停用、无资源、未纳入范围、未巡检、过期、部分和有效完整巡检。不会用“页面刷新成功”代替“指标最新”。
- **业务衔接**：总览中的实时/批作业进入作业页；ECS、DCS、GaussDB 进入监控页。DCS 单实例定位不依赖列表第一页。台账、告警、监控之间切换时固定实际查询范围，浏览器回退恢复对应筛选和详情。
- **界面信息**：指南默认展示含义、单位和限制，技术字段按需展开。告警到监控明确是当前查询，不伪称告警时刻的历史快照。通知详情展示失败和跳过原因，邮件提交服务器不表示终端送达。

职责与扩展规则见《系统结构与监控边界》。覆盖功能复用既有 ResourceGuide、采集开关和巡检证据，不增加另一套能力配置、资源模型或部署依赖。

## 保留的能力边界

AOM 全局停用。DCS 使用版本化原生接口；GaussDB CPU/内存来自已完成原生巡检报告，不冒充实时采样；ECS 没有可用指标源时不补造使用率。所有云操作保持只读。

在线 GaussDB 查询仍要求原有 `ledger:view + task:run`，本轮没有放宽授权。CloudScope/CES 是否适用于用户局点未被公共资料证实。对没有可靠历史定位的页面，保留当前查询提示，不新增推测性的历史接口。

交付沿用已有镜像与独立 `docker-compose`。代码更新包不含镜像、不要求目标机安装 Compose v2、Python 或 npm。
