# DCS、GaussDB 与系统配置更新包

发布日期：2026-11-07。发布标识：`20261107-native-monitoring-1`。应用版本仍为 `0.4.0`。

来源分支为 `refactor/system-coherence`，基线提交 `57601d5`，另包含本次发布复核的类型、刷新和权限修复。本包包含此前代码更新，不需要逐个安装历史补丁。

## 本次内容

| 模块 | 更新 |
| --- | --- |
| DCS | 采集原生逻辑节点，展示分片、主从、Proxy、节点状态和可用区。Redis 4.0 及以上按接口支持情况查询；不支持、未返回、失败和过期分别显示。CPU 折算优先使用实际主节点数量。 |
| DCS 告警 | 增加 `R-DCS-008` 主节点故障、`R-DCS-009` 从节点或 Proxy 节点故障。只在实例运行且有有效节点证据时判定；缺失和未知状态不当作恢复。 |
| GaussDB | 增加原生组件采集及 `R-GS-012` 组件宕机规则。实例列表展示本地采集的磁盘、组件及告警；实例工作区提供磁盘、组件、慢 SQL、会话和巡检报告查询。 |
| GaussDB 页面 | 实例按异常、变更中、停止、正常分组；概况和实例详情优先读取本地采集，不因浏览列表逐个请求云端。CPU、内存仍来自原生巡检报告，不作为实时指标。 |
| ECS 配置 | 各租户的频率、范围、指标配置移到“系统管理 → 巡检任务 → ECS 任务行 → 租户策略”。 |
| 短信配置 | 租户独立网关配置移到“系统管理 → 系统设置 → 租户短信”；同时满足全局和租户开关才发送。已有配置保留，升级不自动开启短信。 |
| 发布修复 | 修正 DCS 节点、新鲜度及 GaussDB 概况、告警汇总的后端类型定义，以及新增前端表格的行类型检查。修复同实例刷新后节点不更新、迟到响应覆盖、租户短信权限入口及总开关保存后的状态刷新；修正 ECS 策略弹窗提醒文字与链接被裁切。 |

云端操作仍为只读查询，不提供会话终止、SQL 执行或扩容操作；所有资源继续禁用 AOM。新生产环境和新租户的采集、巡检默认关闭，原环境已经设置的开关和频率保留。

已开启 DCS / GaussDB 采集的租户，更新后会随原任务开始查询节点 / 组件，并补齐上述三条内置规则。用户修改过的既有规则不被默认值覆盖；若尚未授予新查询接口权限，任务日志会记录失败，页面不能将旧结果当成本轮正常证据。

## 兼容性与迁移

- 沿用既有 ARM64 / Python 3.12 应用运行时镜像。与 `20261106-system-coherence-1` 相比，运行依赖和迁移文件未变。
- 仅上传代码包和校验文件，不需要重新上传镜像。目标机使用 `docker`、独立 `docker-compose` 1.29+、Bash 和常规 Linux 工具，不需要 Compose V2 插件、宿主 Python、Node 或 make。
- 数据库目标版本仍为 `0020`。若已经安装上一版，本次没有新增数据库迁移；更早版本会执行尚未完成的迁移。
- 从 `0018` 之前升级时，仍会清理已下线的 RDS、Kafka、CSS 及旧口径 MRS 作业数据。该清理不能靠 downgrade 恢复，升级前必须保留完整备份。
- 原内置 PostgreSQL 更新入口会先备份。外置数据库须使用原数据库备份流程，更新脚本不会替外置库备份。

## 更新步骤

将以下两个文件上传到同一目录：

```text
hcs-inspector-code-20261107-native-monitoring-1.tar.gz
hcs-inspector-code-20261107-native-monitoring-1.tar.gz.sha256
```

先在上传目录执行校验：

```bash
sha256sum -c hcs-inspector-code-20261107-native-monitoring-1.tar.gz.sha256
```

然后进入**原部署目录**。下面使用默认目录，并将 `/path/` 换为实际上传路径：

```bash
cd /data/hcs-inspector
bash deploy.sh update /path/hcs-inspector-code-20261107-native-monitoring-1.tar.gz
bash deploy.sh status
```

更新入口完成代码清单及离线依赖校验、备份、迁移、初始化、代码切换和服务健康检查。保留原 `.env`、密钥、数据库及租户配置，不执行镜像拉取、构建或导入。

更新后检查：DCS 节点区域、GaussDB 实例及组件、ECS 任务的租户策略入口、系统设置中的租户短信。原来关闭的任务应仍然关闭；开启的任务运行后，再查看本轮时间、结果和日志。

需要回退时保留升级前数据库备份、活动代码指针和旧 `releases/`。跨越 `0018` 的回退须同时恢复数据库与代码，不能只切回旧镜像。
