# 采集与 QPS

本文说明当前实现，不是华为官方配额表。HCS 8.5.1 接口版本与单位见 [接口核对](HCS8.5.1接口核对.md)。

## 限速范围

`hcs/ratelimit.py` 按服务共享平滑限速与在途请求额度。配置 Redis 时跨 API、调度等进程共享；无 Redis 时只保证本进程共享。新建客户端不补充初始突发额度，修改配置也不清空已有等待间隔。

| 项目 | 默认值 | 含义 |
| --- | --- | --- |
| 全局 QPS | 10 | 所有经过云请求保护器的服务合计放行速率 |
| 全局并发 | 4 | 总在途 HTTP 上限 |
| 每服务并发 | 2 | 同一服务跨任务在途上限 |
| 服务 QPS | 通常 5 | IAM、DCS 等分别受服务平滑间隔约束；兼容 CES、CCE K8s 为 10，仍受全局总闸约束 |
| 总尝试次数 | 3 | 包含首次发送、401 重发与瞬时错误重试，非首次加 3 次 |
| 获取额度等待 | 30 秒 | 同时受本请求剩余时间预算约束 |

默认服务键：`dataarts`、`mrs`、`gaussdb`、`dcs`、`ecs`、`evs`、`vpc`、`elb`、`rds`、`dms`、`cce`、`dws`、`css`、`iam` 为 5；`ces`、`cce_k8s` 为 10。CES 默认关闭，列出兼容默认值不代表会发请求。

`5 QPS` 约每 0.2 秒放行一次；`0.1 QPS` 约每 10 秒一次。资源数量、业务 QPS、工作线程数都不是采集 HTTP 次数。列表分页、明细、认证、重试各按一次实际发送计数；只读 POST 也计数。

运行时服务 QPS 在「系统设置 → HCS 采集性能」调整。环境变量 `INSPECTOR_HCS_TOTAL_QPS`、`INSPECTOR_HCS_TOTAL_CONCURRENCY`、`INSPECTOR_HCS_SERVICE_CONCURRENCY`、`INSPECTOR_HCS_MAX_ATTEMPTS` 设置进程级保护。DataArts 明细工作线程数只控制排队工作，不会绕过服务与全局请求总闸。

配置 Redis 后，保护器故障会返回安全错误，不退化为每个进程各自突发放行。Redis 的原子操作使用 Redis 时间；进程退出后的请求租约会过期。具体参数需结合现场网关配额、其他系统流量、响应耗时和任务周期确定。

## IAM Token

- `PASSWORD` 使用 IAM `POST /v3/auth/tokens`，后续服务请求复用 `X-Auth-Token`。`AKSK` 逐请求签名，不换 Token。
- 有效期严格取响应 `expires_at`；缺失、非法、无时区或已到期时拒绝使用，不猜固定 23/24 小时。
- 提前刷新量为取得时剩余寿命的 10%，最多一小时，短 TTL 不会每个业务请求刷新。
- 同认证配置在进程内合并刷新；Redis 可跨进程共享并合并刷新，Token 使用 MASTER_KEY 加密，不明文保存。仍有效的本地缓存命中无需访问 Redis。
- 租户、项目、IAM 地址、账号、凭据和 Endpoint 变化隔离缓存。401 仅刷新拒绝的 generation，旧响应不能使新 Token 失效。
- `TokenProvider` 的 IAM HTTP 同样受限速、并发、总尝试和调用日志保护。共享缓存不可用时不让等待线程反复换 Token。

## DCS 与 AOM

当前局点无 CES，`INSPECTOR_HCS_CES_ENABLED=false`。AUTO 从不预探测或请求 CES；仅旧部署同时显式启用 CES 并选择 CES 时才使用其他服务的兼容路径。DCS 无任何 CES 路径。

DCS 每轮列实例，存在 RUNNING 实例时按项目批量取一次 `/v2/{project_id}/instances/statistic`，不为每个实例额外认证或查询统计。原生内存以 MB 解析，实际样本持久化供历史查询。

AOM 已全局停用，不发起元数据、样本或历史查询，`--all` 也不能启用；旧配置不产生连接告警。没有 AOM 默认 Endpoint 或默认 QPS。当前政策见 [AOM停用说明](AOM停用说明_20261102.md)。

旧 AOM 缓存和历史数据不能作为当前样本来源。DCS 历史只使用本地实际采样；原生查询和租户 Prometheus 沿用各自权限、范围和请求预算，缺失数据不补零。

## 错误与预算

只读接口对白名单瞬时状态和传输失败做有限重试，遵循 `Retry-After` 并将冷却传播给同服务后续请求；等待超过剩余预算时停止，不睡满后继续冲击。401 重发也占总尝试额度；403 不被当成限流反复重试。

粗略估算：单轮需求为分页、明细、认证缺失、可选指标和预期重试总次数 N；平均需求约 N/任务周期。多个任务应合并估算，并给其他系统、失败退避与调度抖动留余量。响应很慢时还受在途并发限制，不能只用 N/QPS 保证完成时间。

## 观察与排障

1. 核对租户、项目、任务与采集开关；没有权限、没有服务、没有映射分别处理。
2. 查看任务 SUCCESS/PARTIAL/FAILED 及缺失指标；未知不等于零，也不能将保留的旧值当本轮新数据。
3. 查看 `stats.hcs.services` 的 calls/errors/rate_limit_ms 与 `cloud.requests.summary`；等待高说明排队，不一定是上游慢。
4. 利用请求 ID 关联 API、任务与上游诊断；日志不记录 Token、AK/SK、密码和完整敏感响应。
5. 429 时按现场配额降速或延长周期，不通过增加客户端或并发绕过总闸。

可选 `PromClient` 同样计入云请求保护器；它的服务键为 `prometheus`，不能用业务吞吐 QPS 替代其查询次数。

当前所有阈值均是项目默认保护，不承诺现场必然具有相同服务配额或 AOM 指标。
