# 用户与人员统一管理

## 目标与边界

用户管理（系统管理 → 用户管理）是平台人员的唯一维护入口。联系人是用户在通知系统中的引用，资源负责人通过用户 ID 关联；新增、改名、邮箱、电话、启停只维护一次。现有角色权限与租户范围继续生效，支持只登记人员而不开通登录。通知组仍由通知配置管理，但只能选择已登记用户。

## 统一入口

- `User` 新增 `phone`、`login_enabled`、`notify_enabled`；`enabled` 为人员总开关。`login_enabled=false` 时禁止登录及已有会话，允许作为负责人或接收通知。登录用户必须设置角色，首次开通必须有密码。
- `Contact.user_id` 一对一关联用户，保留原联系人 ID 与联系组成员关系。联系人页面只读并链接到用户管理；旧联系人写接口返回明确的迁移提示。
- `Resource.owner_user_id` 为负责人稳定标识；`owner` 保留显示名与未匹配历史值。负责人选项来自启用且具有对应租户范围的用户；同名人员用账号区分。不再新增负责人字典。
- `GET /system/user-options?tenant_id=`：有台账/通知权限即可读取安全人员选项，返回 `id, username, display_name, email, phone, enabled, notify_enabled, tenant_ids`。按请求和用户数据范围过滤，不返回角色、密码或登录信息。
- `POST /system/users` 与 `PATCH /system/users/{id}` 支持新字段；账号不可改名，已有管理员保护继续执行。
- `GET /system/users/export`：导出 XLSX；`GET /system/users/import/template`：下载 XLSX 模板；`POST /system/users/import?dry_run=true|false`：预览并原子导入。均需全租户范围的 `user:manage`，最多 5000 行/10MB；错误不部分写入。导出不包含密码，导入按不可变账号匹配，新开通登录需要初始密码，不借导入重置现有密码。
- 导入结果：`total, created, updated, unchanged, error_count, errors:[{row, username, message}], items:[{row, username, action, changes}], dry_run, applied`；预览无写入，确认时重新验证权限、角色、租户与管理员保护。

## 兼容与迁移

新增 0008 迁移，兼容 SQLite / PostgreSQL。优先按唯一邮箱关联已有联系人；无法安全匹配的联系人建为不可登录用户，保留原联系组关系。旧负责人仅在唯一匹配时关联，不凭同名强行合并；未匹配的负责人迁为不可登录人员，歧义保留原文待管理员确认。所有新人员不开通默认密码和额外权限。迁移不修改已发布修订、不改正式环境凭据及采集开关。

## 验收

覆盖用户 CRUD、登录开关/通知开关/总启停、会话撤销、最后管理员保护、人员改名传播、租户范围、通知组引用、台账编辑与 Excel 导入、XLSX 往返/错误行/预览无写入/权限审计、迁移升降级与历史数据。运行 `make check`、数据库迁移验证、真实页面新增与导入导出操作；生成代码更新包沿用现有独立 docker-compose 部署。

## 页面操作

1. 在用户管理新增账号、姓名、邮箱和电话。只登记负责人或通知人员时关闭“开通登录”；角色和密码可留空，不会生成默认密码。
2. 登录账号分配角色和租户范围。总开关控制整个人员状态；登录和通知开关分别控制对应能力。关闭登录使旧会话失效，重新开启不恢复旧会话；已有口令通过“重置密码”维护。
3. 通知管理 → 联系人只查看统一人员及所在组。联系组继续维护成员和组长，选项显示姓名及账号。停用人员保留组关系，路由、升级及待发送通知均检查最新启用状态和租户范围。
4. 资源详情从统一人员中选择负责人；同名人员按账号区分。改姓名同步资源及活动告警，恢复/关闭的历史告警保留原快照。修改邮箱取消待投递的旧地址通知，后续通知使用新地址。
5. 用户管理表头提供下载模板、导入 Excel、导出 Excel；均为真正的 `.xlsx`。导入先预览，整批没有错误才能确认；确认时会重新校验，不支持跳过用户错误行。

## Excel 列与规则

| 列 | 规则 |
| --- | --- |
| 账号 | 唯一匹配键；新用户必填，不改已有账号；文件内不区分大小写查重 |
| 姓名 | 新用户必填；同名可以存在，负责人通过用户 ID 关联 |
| 邮箱、电话 | 留空保留旧值，填写 `-` 清空；邮箱格式与重复校验共用用户管理规则 |
| 启用、允许登录、接收通知 | 是/否、true/false、1/0；新人员默认启用、接收通知、不开通登录 |
| 角色代码 | 使用模板“角色代码”页的代码；不开通登录可留空，已有登录人员不能清空角色 |
| 租户代码 | 使用模板“租户代码”页的代码，多项用英文分号分隔；`ALL` 表示全部、`NONE` 表示空范围；新登录人员必须明确填写范围 |
| 初始密码 | 新开通登录时使用，8–64 字符；已有登录口令不能通过 Excel 重置；导出始终留空，不进入预览、审计或错误回显 |

台账管理字段模板追加“负责人账号”列；有账号时按账号匹配，防止同名混淆。若账号和负责人姓名同时填写，须指向同一用户。旧模板仍支持唯一账号/姓名匹配。未重新分配的历史负责人可以继续保留；改变负责人时必须选择已登记、启用且属于对应租户的人员。

## 历史与部署

- 0008 保留原联系人 ID、联系组成员/组长 ID、资源 ID 和历史管理字段。唯一邮箱能够关联时采用已有用户姓名；匹配不确定时不强行合并。
- 原联系人无匹配账号时建立不可登录人员，保留原通知覆盖范围；只有负责人/字典值的人员不赋予登录权限、角色或默认口令。
- 原负责人字典 JSON 作为历史数据保留，但页面、台账编辑、用户选项及通用系统设置均从用户目录派生负责人，不再接受另建负责人字典。
- 降级保留所有用户与联系组，并关闭不可登录人员的总开关，防止旧代码忽略登录开关造成意外授权。再次升级恢复关联及偏好，不自动重新启用已停用用户。
- 新代码无新增依赖、无需更新镜像。沿用 `bash deploy.sh update 代码包.tar.gz`，目标机仅需 Docker 与独立 `docker-compose`；更新流程自动执行迁移。正式环境数据仅由部署时迁移处理，本次验收使用独立数据库。

## 通知收件人全部引用用户（0009）

| 入口 | 保存的用户引用 | 邮箱来源 |
| --- | --- | --- |
| 联系组、升级组长 | 关联用户的联系人 ID，保留原组关系 | 用户当前邮箱 |
| 租户报表 | `report_user_ids` | 已启用、开启通知且属于该租户的用户 |
| 合并报表、定时报表、平台兜底 | `recipient_user_ids` | 已启用、开启通知、具有全部租户范围的用户 |
| 手动发送报表 | `recipient_user_ids` | 按报表租户范围校验；空选择不回退旧邮箱 |
| SMTP 测试邮件 | `user_ids` | 已登记、启用且开启通知的有效邮箱；测试不含租户资源数据，不要求资源数据范围 |

- 所有人员选择显示姓名、账号和邮箱；不再提供创建联系人或自由新增收件邮箱的输入框。旧客户端传邮箱时只能匹配唯一、已登记且范围合法的用户，不能创建人员或绕过启停。
- 0009 为数据库中的历史收件邮箱关联用户；无法安全匹配时登记为无角色、不可登录的接收人员，保持已有覆盖范围，不扩大已有账号权限。旧邮箱快照保留用于降级，运行时只读用户 ID。
- 用户改邮箱后，报表、平台告警和联系组读取新地址；停用、关闭通知或调整租户范围后，不继续向失效地址投递。已清空租户报表收件人时不会恢复旧邮箱。
- 平台兜底未选择人员时使用可接收邮件的全租户管理员；明确选择的人员全部失效时不扩大投递范围。
- 仅在环境变量配置、未登记为系统用户的旧报表邮箱不会被当作独立联系人使用；应在用户管理登记并在报表设置中选择。
- 告警、恢复、升级、重复通知及测试/报表邮件不再添加 PROD 环境前缀；告警主题和正文使用当前租户信息。积压的告警邮件发送时也重新生成主题。

资源分类映射见 [资源分类映射](资源分类映射.md)：与业务系统、云服务类型及负责人独立维护，不修改已有人工字段。

## 升级短信（0010）

短信也引用统一用户的手机号，不新增短信联系人目录。默认总开关和各租户开关均关闭，按租户独立配置并沿用升级路由。仅手机号人员可以加入联系组；邮件报表仍要求有效邮箱。完整规则与安全边界见 [升级短信通知](升级短信通知.md)。
