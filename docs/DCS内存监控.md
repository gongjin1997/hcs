# DCS 监控（保留内存接口）

## 接口与口径

依据上传的 `dcs-api.pdf`（DCS 2.3.0.2，2025-06-13）。逐项核对见 [DCS原生指标接口核对](DCS原生指标接口核对.md)。

- `GET /v2/{project_id}/instances` 分页读取实例；存在 RUNNING 实例时，再按项目调用一次 `GET /v2/{project_id}/instances/statistic`。
- 统计响应为 `statistics[]`，使用 `instance_id` 关联。`used_memory`、`max_memory` 均为 MB；内存使用率由同一条响应的有效分子、分母计算。
- v2 `used_cpu` 是累计 CPU 秒，不是百分比；不以 v1 同名字段或节点会话数补齐 CPU 使用率、实例连接数。缺失、非法值或零分母保持无数据，真实零保留。
- DCS 实时采集、历史查询和 Excel 导出不调用 AOM、CES 或 Prometheus。旧 DCS 任务的 AOM 配置不再参与采集；可以显式清除，不新增此类配置，不影响其他服务的指标源。

## 历史与 Excel

历史读取 `dcs_memory_sample` 中真实发生的 DCS 原生接口采样，时间字段记录本机获取原生响应的时刻，源端未提供采样时间；不能声称是源端采样时刻，也区别于资源快照刷新时间。每个资源、采样时刻去重，按现有清理策略保留 90 天。

- 开启采集前、关闭采集后或采集失败的时段不补数据；不能用当前快照回填过去。
- 正文第 300–306 页的监控对象接口只返回对象及维度，不是可按时间范围查询指标值的历史接口。
- 展示粒度为 5、10、15、30、60 分钟。平均值按有效原始采样计算，峰值为实际样本最大值；缺口为空，容量取桶内最后一个有效值。
- 只允许查询当前授权范围内 1–20 个 ACTIVE 实例，最长 31 天。同云 ID 按租户、项目、资源记录分别处理。
- `.xlsx` 包含查询条件、实例汇总和内存指标，页面与导出共用查询和权限逻辑；数值可计算，外部名称作为文本，缺口为空。
- 来源 `LOCAL` 显示为“DCS 接口采样”；无记录为 `NONE`。兼容读取旧响应的 AOM/CES 标签，不再产生此类新数据。

## 配置与升级

在租户中配置实际 DCS Endpoint、授权项目及认证信息，并按需开启系统采集、租户采集和 DCS 任务。页面不要求配置 AOM，也不因缺少 AOM 映射提示接入异常。

新增 DCS 专属迁移 `0012`（`down_revision=0011`），创建原生统计实际采样表；原内存表和接口保留。不回填已有快照；无新增依赖或基础设施。升级至当前迁移 head 后使用。代码更新后重启 API、调度和通知进程，使用独立 `docker-compose`。本轮仅使用隔离数据库和合成云响应验证，未连接正式 HCS 或更改正式配置。


## 原生当前统计与完整指标

新 API/字段合同见 [DCS监控合同_20261102](DCS监控合同_20261102.md)。菜单名称为“DCS 监控”，路径仍为 `/dcs`。

- 当前实例保留 CPU 累计秒、内存使用率及 MB、网络 kbit/s、keys、GET/SET 累计次数。V1 CPU% 尚未启用，无自动跨版本 fallback。
- 当前值必须有明确的 DCS V2 来源与本地原生响应获取时间；不能以 `last_seen` / `snapshot_at` 续期。过期或旧 AOM/CES 快照的当前数值为空；本地获取时间、状态与说明仍可查看。
- 原生采样表 `dcs_metric_sample` 与原内存表独立。新指标历史 `/api/v1/dcs/metrics/history` 只读此表，原内存历史 `/api/v1/dcs/history` 仍读旧表。未启用完整采样前的全指标历史为空，不自动回填。
- `/api/v1/dcs/metrics/export` 复用完整指标查询，输出查询条件、指标口径、当前统计、原生指标四个工作表；`/api/v1/dcs/export` 的内存工作表合同不变。
- 内存使用率、已用内存和网络速率取窗口均值；CPU累计秒、keys、命令数与容量取最后一个有效样本，另外保留本地响应获取时间与每指标有效样本数。计数重置保留原值，不推算 CPU% 或 QPS。
- 两类样本均按 90 天分批清理，并清理已释放资源及孤儿；迁移不会删除旧内存样本。Excel 和页面以同一时段、同一租户/项目权限查询。
