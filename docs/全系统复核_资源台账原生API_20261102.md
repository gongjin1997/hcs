### ELB 通用分页的结论

实际复读并渲染了 `elb-api.pdf` 物理12、13、41、47页，页脚分别为印刷2、3、31、37页：

1. §1.4 虽介绍 limit/marker 或 limit/offset，但明确要求参考单个 API 参数。
2. 通用说明只称超过“接口支持的最大数量”会报403，没有给这个 V3 列表的具体最大值；“建议不超过1000”不是该接口上限。
3. 表5-2只有 cluster_id，没有声明 limit、marker、offset、默认页长或最大值。
4. 表5-13的 current_count 是当前记录数；next_marker 是当前结果最后一条记录 ID。

因此没有把通用分页直接套到 ELB V3，也没有把 next_marker 非空当“下一页存在”。保留无额外参数的原生查询及一致性检查。**真实局点是否有未公开默认截断，以及如何取得全部页，仍是证据缺口**；必须补同版补丁文档或经授权的只读现场证据。不能用本地合成响应宣称已证明真实上限。

### CSS 旁证与兼容配置边界（主代理补查）

主代理补充：较新公有云文档采用offset；老吉隆坡文档及HCS Online 2024.9.0 PDF采用start，表示从第N个集群的起始索引查询，**不是页号**。这些来源均不是现场HCS8.5.1版次，本专项仅记录为风险旁证，没有以其认证或改写当前接口。主代理提供的公开官方文档路径为：

```text

```

当前代码硬编码`mode="page", start=1`，每次start加1；**没有已实现的CSS接口族兼容配置项**。因此不能把“保留旧实现”写成“已显式选定并验证某一版次”。一旦现场契约实际使用start记录索引，当前递增方式存在重叠页/遗漏或同步失败风险；当前防重复保护不能证明清单完整。不能仅凭本地合成响应、totalSize一致或第一页正常关闭该缺口。
