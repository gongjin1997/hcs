# AOM 停用说明

日期：2026-11-02。发布标识：`20261102-aom-disabled-1`。

## 当前政策

所有资源暂时停用 AOM，包括 ECS、DCS、GaussDB、MRS、CCE 等。即使保存了 AOM Endpoint、任务映射、采集策略、成功的能力探测结果或缓存，也不能启用 AOM 请求。底层客户端在鉴权、地址解析和网络请求前拒绝 `service=aom`；选源忽略 AOM。

此政策覆盖此前所有“显式 AOM 可用”“ECS 有专用映射即可使用”“可通过租户检测或 probe 验证 AOM”的实现结论，包括 2026-11-02 同日较早的核对记录。旧文档保留的 API 契约只是历史参考，不是启用入口，也不是正式环境兼容证明。

## 配置及兼容

- 活动来源与能力列表移除 AOM，不再推荐或提供 AOM 配置入口。
- 新建租户或显式修改 `metrics_source=AOM` 被拒绝。数据库原有 AOM 值保留，普通无关编辑可以继续；返回 `metrics_effective=NONE`、`metrics_source_disabled=true` 和停用说明。
- 旧能力记录仍保留在数据库；接口输出不把原来的 `aom.available=true` 当作当前能力。
- `AUTO` 忽略旧 AOM 地址和映射。已配置租户 Prometheus 时仍可使用，未配置时有效来源为 `NONE`；不猜测或补造其他来源。
- 所有任务的新非 null `aom` 参数被拒绝，不受任务代码或映射是否有效影响。`aom:null` 只删除旧映射，其他参数保留；普通周期、cron、启停编辑不重写无关参数。ECS 采集策略遵循同一政策。
- 新租户既有采集、巡检默认关闭策略不变。没有数据库 schema 迁移，不批量改写正式租户。

## 检测、历史和各服务

租户连通性检测不请求 AOM，也不因旧 AOM 地址不可达而报警。存在旧配置时返回 `state=skipped`、`available=false`、`disabled=true`，不覆盖旧探测记录。其他服务的真实认证或接口错误继续按原规则报告。

probe 保留一个停用条目用于解释 `--only aom` 的结果；`--all` 或 `--raw` 不能绕过。只选择停用的接口时，在客户端构造前跳过，不触发认证、地址解析或网络调用。

旧 AOM 采样、运行记录和审计不删除，可按历史查看；不能回填当前快照、续接当前曲线或作为当前告警判断证据。没有数据时保持缺失，不补零或伪造恢复。

DCS 继续使用原生实例与运行统计及本地实际采样历史。GaussDB 继续使用原生状态、磁盘、组件、慢 SQL、只读会话和已有巡检报告；CPU/内存报告不当作实时使用率。ECS 的状态、台账、项目配额不依赖 AOM；使用率可来自已配置的租户 Prometheus。旧 CES 兼容开关不因本次变更自动开启。

演示初始化不注册 AOM 地址或映射，仅使用进程内 Mock 和明确标记的合成 Prometheus 数据。它不能证明正式局点支持任意指标。

## 验证与部署边界

本次验证使用临时数据库、MockTransport 或进程内 Mock；未读取真实 `.env`、正式数据库、密钥，未调用正式 HCS、SMTP 或短信服务。不存在“正式 AOM 接口已验证可用”的证据，也不据本文宣布正式环境已完成联调。

发布沿用既有镜像和独立 `docker-compose` 命令，不需要 `docker compose` v2 插件。`20261102-aom-disabled-1` 代码包由主流程构建并校验；正式更新前按既有运维流程备份，本文不表示已经修改或更新正式环境。
