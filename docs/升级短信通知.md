# 升级短信通知

## 开关与租户隔离

短信默认关闭。系统设置中的“升级短信总开关”和对应租户的“开启升级短信”同时开启，且租户本身已启用时，才会处理短信。

每个租户独立保存完整网关/代理地址、短信账号、加密密码、扩展端口、TLS 验证及告警级别。配置不借用 HCS 账号或 HCS 证书验证设置；密码只写不读，留空保留，清除密码需先关闭租户短信。没有默认公网网关地址。

总开关关闭时保留各租户配置；一个租户关闭、凭据错误或网关失败，不把短信改投其他租户网关。配置界面没有发送测试短信或重发按钮。

## 触发规则

- 首期只处理未认领告警的升级短信，不发送初始告警、恢复或常规重复短信。
- 沿用通知路由的租户、服务、级别匹配及升级分钟数；到时通知该步的组长或指定联系组成员。
- 默认选择 P1、P2，租户可以调整；还须同时符合通知路由升级步骤的级别要求。
- 只处理开关启用后新触发或重新触发的告警，不补发启用前的历史积压。
- 已认领、恢复、关闭、静默或处于维护窗口的告警不发送。入队与提交网关前都复核。
- 人员继续从用户管理维护。只选择已启用、通知开启、范围覆盖该租户并拥有有效手机号的用户，支持仅手机号人员。
- 固定电话、空号及多个号码混填不投递；支持大陆手机号码及 +86/86 前缀的规范化。短信记录只保存掩码，不复制独立联系人。

## 投递与结果

使用上传的《云信网关 HTTP3.0 协议接入用户手册》§4.1 群发接口；网关和代理须由短信平台管理员按接入指引提供。协议签名、字段及状态边界见 [云信短信协议核对](云信短信协议核对.md)。

每个告警轮次、路由升级步骤、用户仅入队一次；提交前持久化处理状态，避免多个工作进程重复提交。短信处理有单轮时间预算和租户公平限制，不能长期阻塞邮件。

| 状态 | 含义 |
| --- | --- |
| 待处理 | 已入队，尚未调用网关 |
| 处理中 | 已抢占并持久化，正在处理 |
| 网关已受理 | 网关明确确认该号码受理；不等同手机送达 |
| 失败 | 网关明确拒绝或配置不可用 |
| 结果待核对 | 请求超时、异常响应或进程中断，不能确认是否已受理 |
| 已跳过 | 开关关闭、配置变更、人员失效或告警已不满足条件 |

超时、未知结果和失败不自动重试；`smsBatchId` 在文档中是关联字段，并非幂等承诺。账号、签名、停用、过期、余额或报备 IP 等配置错误会阻断该配置修订，等待管理员更新配置，避免连续错误请求造成账号锁定。

首期未接入供应商回执，界面不会显示“已送达”。回执文档的状态样例与字段表存在差异，应在后续接入前确认含义、鉴权和防重放规则。

## 内容与接入准备

固定摘要包含租户、级别、服务、告警标识和未认领时长，不自动加入平台链接、资源名称或联系人电话。接入指引要求链接和联系电话单独报备，默认摘要避开这些内容。

接入前需要完成短信平台应用申请、网络及安全网关策略，并为各租户配置对应的账号和地址。现有代码不会自行开通网络、申请账号或调用文档中的示例公网地址。

## 升级、记录和降级

0010 新建短信 Outbox，并补齐仅手机号人员的联系人投影；不启用短信，不写入网关凭据，不改变原联系组 ID。后台使用现有 notifier 进程，无需新增容器或基础设施。

租户短信配置可查看近期掩码记录。短信密码使用现有 AES-256-GCM 主密钥加密，接口、审计及错误日志不返回口令、签名、完整号码或网关响应正文。

显式降级到 0009 会删除短信待发及发送记录，并关闭总开关，保留用户、联系组及租户配置。再次升级后需要重新确认启用，防止旧队列丢失去重信息后补发历史短信。

本地协议与业务测试使用合成数据和 MockTransport，不发送真实短信；正式网关是否可达、账号授权和实际运营商送达需配置完成后由接入方核验。
