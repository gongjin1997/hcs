# HCS-Inspector 部署运维手册（v0.4，独立 docker-compose）

> 2026-11-02：`20261102-aom-disabled-1` 对所有资源（含 ECS）停用 AOM。无需补填 AOM 地址或映射；旧 AOM 选项有效为 NONE，AUTO 可继续使用已配置租户 Prometheus。租户检测与 probe 跳过 AOM，`--all` 不启用。旧记录仅供历史，详见 [AOM停用说明](AOM停用说明_20261102.md)。

适用对象：负责安装、升级、备份和日常维护平台的运维同事。所有命令都在**部署目录**（默认 `/opt/hcs-inspector`，即仓库的 `deploy/` 目录或离线包解压目录）执行。

## 1 部署架构

一台 Linux 虚拟机运行 7 个容器：`postgres`、`redis`、`migrate`（一次性）、`api`、`scheduler`、`notifier`、`web`（nginx，唯一对外端口）。
数据在 `DATA_DIR`（默认 `./data`），备份在 `BACKUP_DIR`（默认 `./backups`），配置与密钥在 `.env`。详见《架构文档》第 3 章。

## 2 环境准备

| 项 | 要求 |
| --- | --- |
| 主机 | 1 台 Linux 虚拟机（CentOS 7.9+ / openEuler / Kylin / Ubuntu 20.04+ 均可），4 核 8 GB 起，系统盘 50 GB + 数据盘 100 GB（挂载到部署目录或 `DATA_DIR`） |
| 软件 | Docker 20.10+、独立 `docker-compose` 1.29+、GNU make、openssl、tar |
| 时间 | 开启 NTP，时区 Asia/Shanghai（AK/SK 签名、Token 过期、定时任务依赖时钟） |
| 账号 | 用有 docker 权限的运维账号执行（`docker` 组或 root） |
| 网络 | 见下表；HCS 侧需提前开通平台主机到各租户 API 网关的访问 |

| 方向 | 端口 | 用途 |
| --- | --- | --- |
| 运维办公网 / 堡垒机 → 本机 | 80（HTTP）/ 443（HTTPS） | 控制台、大屏、邮件里的认领链接 |
| 本机 → 各租户 IAM、服务 Endpoint | 443 | 巡检、台账同步（只读 OpenAPI） |
| 本机 → CCE 集群 K8s API | 集群 API 端口（经 CCE API 网关为 443） | 容器事件（可选） |
| 本机 → 租户 Prometheus | 9090 等 | 仅“指标来源 = Prometheus”的租户 |
| 本机 → SMTP | 25 / 465 / 587 | 告警、报表邮件 |
| 内网 Prometheus → 本机 | 80 / 443（`/metrics`） | 平台监控（可选） |

## 3 获取安装包

ARM64 正式环境使用 `hcs-inspector-<版本>-arm64-offline.tar.gz`：解压后执行 `bash deploy.sh`，无需目标机联网或安装 make / Python / Node。已有部署保留原 `.env`、数据目录、项目名和证书配置；不导入演示数据。完整步骤见 [ARM64离线部署.md](ARM64离线部署.md)。

| 方式 | 步骤 |
| --- | --- |
| 离线包（推荐，内网局点） | 构建机执行 `bash deploy/scripts/offline-bundle.sh` → 得到 `deploy/dist/hcs-inspector-<版本>-arm64-offline.tar.gz`（四个 ARM64 镜像 + 校验文件 + 一键部署脚本）；目标机解压后执行 `bash deploy.sh` |
| 私有镜像仓库 | 拷贝 `deploy/` 目录到目标机；`.env` 设置 `IMAGE_PREFIX=harbor.example.com/ops/hcs-inspector`，`docker login` 后安装 |
| 源码构建 | 目标机能访问软件源时，在仓库 `deploy/` 目录直接 `make install`（检测到没有镜像会从源码构建；可在 `.env` 配 `PIP_INDEX_URL` / `NPM_REGISTRY` 镜像源） |

## 4 首次安装

当前 ARM64 发布入口为 `bash deploy.sh`，支持独立 `docker-compose`，不要求插件、make 或宿主 Python/Node。新生产库全局采集及巡检任务默认关闭；已配置旧环境的开关不重置。后续仅上传小代码包并执行 `bash deploy.sh update 代码包.tar.gz`，无需重复传镜像。旧首包一次性脚本补丁和详细命令见 [ARM64离线部署.md](ARM64离线部署.md)。

```bash
cd /opt/hcs-inspector
make gen-env          # 1. 生成 .env：随机数据库口令、JWT / 邮件链接密钥、/metrics 令牌、凭据主密钥、admin 初始口令（权限 600）
vi .env               # 2. 修改必改项（见第 5 章）：INSPECTOR_BASE_URL、SMTP_*；HCS 内部 CA → certs/hcs-ca.pem + INSPECTOR_HCS_CA_FILE
make install          # 3. 检查环境 → 载入 / 构建镜像 → 启动 postgres、redis → 迁移 + 初始化 → 启动 api、scheduler、notifier、web → 健康检查
make status           # 4. 确认全部正常（退出码 0）
```

`make install` 可重复执行（已安装时相当于“对齐配置并重启”）。安装完成后：

1. 浏览器打开 `INSPECTOR_BASE_URL`，用 `admin` + `.env` 里的 `INSPECTOR_INIT_ADMIN_PASSWORD` 登录，**立即修改口令**，然后把 `.env` 中该行清空（之后执行 `make up`）。
2. **离线备份 `.env`**（尤其 `INSPECTOR_MASTER_KEY`）：丢失后已保存的租户凭据无法解密，只能重新录入。
3. 通知管理 → SMTP 与测试邮件：发一封测试邮件确认 SMTP 可用。
4. 系统管理 → 用户管理：统一登记用户、联系人与资源负责人；按需开通登录、分配角色与租户范围，可通过 Excel 模板批量导入或导出。只接收通知/负责资源时关闭登录，无需角色和密码。
5. 系统管理 → 租户接入：录入租户（见《联调手册》），点“连通性测试”；`make probe TENANT=<编码>` 做接口字段核对。
6. 通知管理：配置联系人、联系组、通知路由（按租户 / 服务 / 级别）与未认领升级。
7. 系统管理 → 采集开关：新租户建议先只开台账，核对无误后再逐类打开巡检。

## 5 `.env` 配置说明

| 分组 | 变量 | 说明 |
| --- | --- | --- |
| compose | `COMPOSE_FILE` | 叠加哪些 compose 文件：`docker-compose.yml`（HTTP）/ `docker-compose.yml:docker-compose.https.yml`（HTTPS）；`docker-compose.demo.yml` 仅演示 |
| | `HCS_INSPECTOR_VERSION`、`IMAGE_PREFIX` | 镜像版本与名称前缀（`<前缀>-backend`、`<前缀>-web`）；`make upgrade V=` 会自动修改版本 |
| | `DATA_DIR`、`BACKUP_DIR`、`BACKUP_KEEP` | 数据目录、备份目录、备份保留份数（默认 14） |
| | `WEB_BIND`、`WEB_PORT`、`WEB_HTTPS_PORT` | 控制台监听地址与端口（默认 0.0.0.0:80 / 443） |
| | `TZ`、`API_WORKERS` | 容器时区；API 进程数（默认 2） |
| 数据库 | `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` | gen-env 生成随机口令；安装后不要再改口令（改了需同步修改数据库内用户口令） |
| 安全 | `INSPECTOR_ENV=prod` | 生产模式：密钥不合格拒绝启动、忽略演示数据、登录页不显示账号 |
| | `INSPECTOR_JWT_SECRET`（≥ 32 位）、`INSPECTOR_MAIL_LINK_SECRET`（≥ 16 位） | 登录令牌、邮件认领链接签名；修改后所有人需重新登录、旧邮件链接失效 |
| | `INSPECTOR_MASTER_KEY` | 租户凭据加密主密钥（base64 32 字节）；**不可修改、必须离线备份** |
| | `INSPECTOR_INIT_ADMIN_PASSWORD` | 只在系统中还没有任何用户时创建 admin；首次登录后清空 |
| | `INSPECTOR_METRICS_TOKEN` | `/metrics` 的 Bearer 令牌 |
| | `INSPECTOR_LOGIN_MAX_FAILURES`、`INSPECTOR_LOGIN_LOCK_MINUTES` | 连续输错锁定（默认 5 次 / 10 分钟） |
| 访问 / 邮件（必改） | `INSPECTOR_BASE_URL` | 邮件中“查看详情 / 认领”链接前缀，必须是运维手机和电脑都能打开的地址 |
| | `INSPECTOR_ENV_TAG` | 兼容旧配置保留；邮件主题使用租户信息，不再添加环境前缀 |
| | `INSPECTOR_SMTP_HOST`、`_PORT`、`_STARTTLS`、`_USER`、`_PASSWORD`、`_SENDER`、`_REPLY_TO`、`_CA_FILE` | SMTP；内部 CA 放 `certs/smtp-ca.pem` |
| | `INSPECTOR_REPORT_MAIL_TO` | 合并报表初始收件人（JSON 数组）；上线后在页面维护 |
| HCS | `INSPECTOR_HCS_SCHEME`、`INSPECTOR_HCS_VERIFY`、`INSPECTOR_HCS_CA_FILE` | 协议与证书校验；内部 CA 放 `certs/hcs-ca.pem`，不建议关闭校验 |
| | `INSPECTOR_HCS_REGION`、`INSPECTOR_HCS_EXTERNAL_DOMAIN` | 默认 Region 与外部域名（Endpoint 模板 `{region}` / `{domain}`，邮件里的控制台链接） |
| | `INSPECTOR_HCS_ENDPOINTS` | 服务 Endpoint 模板（JSON，整体覆盖）；个别租户不同可在“租户接入”里单独覆盖 |
| 其他 | `INSPECTOR_TIMEZONE`、`INSPECTOR_DEMO_SEED=false`、`INSPECTOR_CORS_ORIGINS=[]` | 一般不用改 |

> 修改 `.env` 后执行 `make up`（只重建配置有变化的容器）。租户、任务周期、采集开关、通知、静默、保留天数、报表时间等**都在页面维护**，不需要改 `.env`。

## 6 HTTPS

1. 证书放 `nginx/certs/server.crt`（含中间证书链）和 `nginx/certs/server.key`（权限 600）；没有正式证书时可按 `nginx/certs/README.md` 自签。
2. `.env`：`COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml`，`INSPECTOR_BASE_URL=https://...`。
3. `make up`。HTTP 80 自动 301 跳转 HTTPS；启用 TLS 1.2 / 1.3 与 HSTS。
4. 更换证书：覆盖两个文件后 `make reload-web`（先 `nginx -t` 检查再热加载，不中断服务）。

## 7 访问控制与安全加固

| 项 | 操作 |
| --- | --- |
| 来源白名单 | 编辑 `nginx/snippets/allowlist.conf`：`allow 10.10.0.0/16;`（办公网）、`allow <堡垒机 IP>;`，最后 `deny all;` → `make reload-web`。邮件认领链接需要手机能访问时，把手机所在网段（VPN / WiFi）也加入 |
| `/metrics` | 默认拒绝；见第 8 章 |
| 主机防火墙 | 只放行 80 / 443（与 SSH）；数据库、Redis、API 不映射端口 |
| 密钥 | `.env` 权限 600、离线备份；不要把 `.env` 发到群里或工单 |
| HCS 账号 | 只读权限（各服务 ReadOnly + CES 读 + CCE 集群只读 RBAC）；定期轮换口令 / AK（在“租户接入”更新，立即生效） |
| 平台账号 | 按最小权限分配角色；离职人员停用；admin 只给平台管理员 |
| 审计 | 系统管理 → 操作审计；保留期在系统设置里调整（不少于 90 天，建议 180 天以上），需要长期留存的定期导出 |
| 生产自检 | `INSPECTOR_ENV=prod` 时密钥不合格、缺主密钥或使用 SQLite 会拒绝启动（日志里有中文原因） |

## 8 监控对接（Prometheus）

平台提供 `GET /metrics`（Prometheus 文本格式）。nginx 默认拒绝，接入步骤：

1. `nginx/snippets/metrics-allow.conf` 在 `deny all;` 前加 Prometheus 服务器：`allow 10.10.8.20;` → `make reload-web`。
2. Prometheus 抓取配置（令牌取 `.env` 的 `INSPECTOR_METRICS_TOKEN`）：

```yaml
scrape_configs:
  - job_name: hcs-inspector
    scheme: https                    # HTTP 部署改为 http
    metrics_path: /metrics
    scrape_interval: 60s
    authorization:
      type: Bearer
      credentials: "<INSPECTOR_METRICS_TOKEN>"
    tls_config:
      ca_file: /etc/prometheus/inspector-ca.pem   # 自签证书时
    static_configs:
      - targets: ["inspector.example.com:443"]
```

3. 告警规则示例：

```yaml
groups:
  - name: hcs-inspector
    rules:
      - alert: InspectorDown
        expr: up{job="hcs-inspector"} == 0
        for: 5m
        labels: {severity: critical}
        annotations: {summary: "巡检平台 /metrics 无法访问"}
      - alert: InspectorWorkerHeartbeat
        expr: hcs_inspector_worker_heartbeat_age_seconds > 300
        for: 2m
        annotations: {summary: "{{ $labels.worker }} 心跳超时（调度 / 通知进程可能已停止）"}
      - alert: InspectorNotifyBacklog
        expr: hcs_inspector_notification_oldest_pending_seconds > 900
        for: 5m
        annotations: {summary: "告警邮件积压超过 15 分钟（检查 SMTP）"}
      - alert: InspectorTaskFailing
        expr: hcs_inspector_task_consecutive_failures >= 3
        annotations: {summary: "{{ $labels.task }}（{{ $labels.tenant }}）连续失败 {{ $value }} 次"}
```

| 指标（前缀 `hcs_inspector_`） | 标签 | 含义 |
| --- | --- | --- |
| `info` | version、env | 版本 |
| `alarms_active` | tenant、service、severity、status | 活动告警数（告警中 / 已认领 / 已抑制） |
| `alarms_fired_24h` | severity | 近 24 小时新告警 |
| `notifications_backlog` / `notifications_24h` | status | 待发 / 重试中的通知；近 24 小时通知 |
| `notification_oldest_pending_seconds` | — | 最早未发通知的等待时长 |
| `task_last_run_timestamp_seconds` / `task_last_success_timestamp_seconds` / `task_last_duration_seconds` / `task_last_status` / `task_consecutive_failures` | task、tenant（status） | 任务最近执行情况 |
| `worker_heartbeat_age_seconds` | worker、host | 调度 / 通知进程心跳间隔 |
| `resources` | tenant、type、health | 在用资源数 |
| `silences_active` | — | 有效的静默 / 维护窗口数 |
| `sse_subscribers`、`http_requests_total`、`http_request_duration_seconds` | method、code | 本进程实时连接数、请求数与耗时（多 API 进程时为抓到的那个进程） |

> 平台自身也会告警（R-PLAT-001 ~ 004，邮件通知），Prometheus 主要用于“平台整体不可用”这类平台自己发不出告警的场景。

## 9 日常运维

| 频率 | 动作 |
| --- | --- |
| 每天 | 看“运行总览”与邮件；`make status` 或“系统管理 → 平台状态”无异常；确认凌晨备份成功（`ls -lt backups/ \| head`） |
| 每周 | 看周报；处理“疑似闲置”和“未分配负责人”的台账；检查长期未恢复 / 反复复发的告警，调整规则或建静默 |
| 每月 | 恢复演练（第 11.3 节）；检查磁盘（`df -h`、`du -sh data backups`）；HCS 账号口令 / AK 到期检查 |
| 变更前 | 在“维护与静默”建维护窗口；变更后确认告警恢复 |

常用命令：

| 命令 | 说明 |
| --- | --- |
| `make status` | 容器健康 + 平台自检（进程心跳、通知积压、任务连续失败、平台告警、迁移版本）；退出码 0 正常 |
| `make ps` / `make logs S=api` | 容器列表 / 日志（`api` `scheduler` `notifier` `web` `postgres` `redis` `migrate`） |
| `make restart [S=notifier]` | 重启应用进程 |
| `make up` | 修改 `.env` 后按新配置重建容器 |
| `make reload-web` | 修改 `nginx/` 配置后检查并热加载 |
| `make migrate` | 手动执行迁移 + 幂等初始化 |
| `make probe TENANT=<编码> [ONLY=ecs,dcs] [LIMIT=20]` / `make probe-list` | HCS 接口探测，报告在 `exports/` |
| `make shell` / `make psql` | 进入 api 容器 / 连接数据库（修改数据前先备份） |
| `make config` | 打印合并后的 compose 配置（含密钥，勿外发） |

## 10 升级与回滚

```bash
# 离线包：新版本离线包解压到临时目录，然后
#   1) 用新包的 images/ 目录替换部署目录的 images/
#   2) 覆盖 scripts/、docker-compose*.yml、Makefile、README.md、docs/、nginx/http.conf、nginx/https.conf、
#      nginx/snippets/hcs-app.conf、nginx/snippets/security-headers.conf
#   3) 保留 .env、data/、backups/、certs/、nginx/certs/、nginx/snippets/allowlist.conf、nginx/snippets/metrics-allow.conf（局点自定义）
make upgrade V=0.4.1
make status
```

`upgrade` 过程：**备份**（旧版本，失败则中止；确认风险可 `SKIP_BACKUP=1`）→ 更新 `.env` 版本号 → 载入新镜像 → **新版本先执行迁移**（旧进程继续运行；PostgreSQL 上迁移失败整体回滚，`.env` 版本号自动改回，旧版本继续服务）→ 依次替换 scheduler / notifier → api → web → 健康检查 → `make status`。

回滚（新版本已完成迁移但运行异常）：

```bash
make rollback V=0.4.0 F=backups/hcs-inspector-<升级前时间>.tar.gz
```

`rollback` 把 `.env` 版本号改回旧版本 → 确认旧版本镜像 → 用**升级前备份**恢复数据库（需输入 yes）→ 启动旧版本。
新版本迁移过的数据库旧版本无法直接使用，因此回退必须配合升级前备份（`upgrade` 结束时会打印备份文件名）；升级后产生的新数据（告警、台账变化）会丢失，回退后下一轮巡检会重新采集。

升级前请阅读 `CHANGELOG.md` 的“变更 / 已知限制”；跨多个版本可直接升级到目标版本（迁移按顺序执行）。

## 11 备份与恢复

### 11.1 备份

```bash
make backup            # → backups/hcs-inspector-<时间>.tar.gz：db.dump（pg_dump -Fc）+ .env + nginx 配置 / 证书 + compose 文件；保留 BACKUP_KEEP 份
```

crontab（每天 02:00，与 03:30 的数据清理错开）：

```
0 2 * * * cd /opt/hcs-inspector && make backup >> backups/backup.log 2>&1
```

备份包含 `.env`（密钥），请把 `backups/` 同步到另一台主机或备份系统，并限制访问权限。

### 11.2 恢复

```bash
make restore F=backups/hcs-inspector-20261001-020000.tar.gz            # 使用当前 .env
make restore F=backups/hcs-inspector-20261001-020000.tar.gz WITH_ENV=1 # 同时恢复备份里的 .env（新主机恢复时用）
```

过程：校验备份 → 比较 `INSPECTOR_MASTER_KEY`（与备份不一致会警告：恢复后租户凭据无法解密）→ 输入 `yes` 确认 → 停应用 → 重建数据库并 `pg_restore` → 迁移到当前版本 → 启动 → 健康检查。

### 11.3 恢复演练 / 迁移到新主机

1. 新主机按第 2 章准备环境，拷贝部署目录（含 `images/`）与最近一份备份。
2. `make restore F=<备份> WITH_ENV=1` → `make status` → 登录核对：告警、台账、报表、租户“连通性测试”。
3. 切换 DNS / 访问地址；如地址变化同步修改 `INSPECTOR_BASE_URL`。演练结束记录耗时（RTO）与数据时间点（RPO）。

## 12 数据保留与容量

“系统管理 → 系统设置 → 数据保留”调整各类数据保留天数（默认：运行记录 / 通知 90 天、已结束告警 / 审计 180 天、台账变更 / 已释放资源 / 报表 365 天、容器事件 30 天），
每天 03:30 的“数据清理”任务分批删除，删除行数在“巡检任务 → 数据清理 → 运行记录”中查看。磁盘使用超过 70 % 时：缩短保留天数、清理旧备份或扩容数据盘。

## 13 故障排查

| 现象 | 排查 | 处理 |
| --- | --- | --- |
| 页面打不开 | `make ps`、`make logs S=web`；白名单是否拦截（403） | 修正 `allowlist.conf` 后 `make reload-web` |
| 登录提示“服务器内部错误” | `make logs S=api`，按 `request_id` 查 | 多为数据库不可用：`make logs S=postgres` |
| api 启动失败，日志提示生产配置不合格 | `.env` 中 JWT / 邮件链接密钥过短、缺 `MASTER_KEY` | 用 `make gen-env` 生成的值；不要用示例值 |
| 任务全部失败 / R-PLAT-002 | 租户“连通性测试”；`make probe TENANT=...` | 口令过期 / AK 失效 / 网络不通 / 证书不受信（配置 `INSPECTOR_HCS_CA_FILE`） |
| 某类资源一直 FAIL | 探测报告中该接口的错误和缺失字段 | 先在“采集开关”关闭该类，联系开发修正字段映射 |
| 收不到邮件 / R-PLAT-003 | 通知管理 → 最近通知（状态、错误）；SMTP 测试邮件 | SMTP 地址、端口、STARTTLS、账号、发件人白名单 |
| 告警没有通知 | 通知管理 → 路由模拟：是否命中路由、是否被静默 | 补路由 / 联系人；检查静默是否过宽 |
| 邮件认领链接打不开 | `INSPECTOR_BASE_URL` 是否手机可达；链接是否超过 24 小时 | 修改 BASE_URL 后 `make up`；在页面认领 |
| R-PLAT-004 心跳超时 | `make ps`（scheduler / notifier 是否 unhealthy）、`make logs S=scheduler` | `make restart S=scheduler`；持续出现检查数据库 / 磁盘 |
| 实时推送不刷新 | 浏览器 Network 中 `stream/alarms`；nginx 是否被中间代理缓冲 | 中间若有其他代理需关闭缓冲（`X-Accel-Buffering: no`） |
| 磁盘满 | `du -sh data/* backups` | 清理旧备份、缩短保留天数、扩容；Docker 日志已限制 50 MB × 5 |
| 迁移失败（升级时） | `make logs S=migrate` | 旧版本仍在运行；保留输出联系开发，修复后重新 `make upgrade` |

需要开发协助时提供：`make status` 输出、相关容器日志片段（`make logs S=xxx`，注意去掉敏感信息）、探测报告 `exports/probe-*.json`（已脱敏）、版本号。
