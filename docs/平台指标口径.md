# 平台指标口径

资源级指标、规则事实、属性、容量与排障建议见 [资源与指标指南](资源与指标指南.md)；采集限流见 [采集与 QPS 最佳实践](采集与QPS最佳实践.md)。本文补充总览、作业报表和平台运行指标。口径以当前代码为准，不代表业务可用率或云平台官方配额。

## 总览和大屏

除平台配置和任务定义外，业务统计受当前用户的租户权限及顶栏租户选择共同限制。来源：`backend/app/services/dashboard_service.py`。

| 指标 | 单位 | 当前口径与限制 |
| --- | --- | --- |
| 巡检对象 | 个 | 在用、monitored=true，且资源类型已配置健康分组的资源；不等于全部台账资源 |
| 异常资源 | 个 | 有未抑制活动告警关联的资源 ID 去重；同一资源多个告警只算一个 |
| 活动告警 / P1–P4 | 条 | FIRING、ACKED、SUPPRESSED 三种状态，按当前告警级别计数；含抑制中的记录 |
| 待认领 | 条 | 状态为 FIRING 的活动告警；不包含已认领和已抑制 |
| 今日新增 | 条 | first_seen 在平台配置时区当天零点后；不按最后触发时间计数 |
| 近 24 小时趋势 | 条/小时 | 按 first_seen 分桶；24 个小时桶含当前小时；重复触发 count 不展开为新增告警 |
| MTTA / 平均认领时长 | 分钟 | first_seen 在最近 24 小时内且已有 ack_at 的样本，求 ack_at-first_seen 平均值；未认领不参与；空样本为 null |
| MTTR / 平均恢复时长 | 分钟 | first_seen 在最近 24 小时内且已有 resolved_at 的样本，求 resolved_at-first_seen 平均值；未恢复不参与；空样本为 null |
| 近 24 小时恢复 | 条 | 最近 24 小时首次产生、且已有恢复时间的样本；不是所有在最近 24 小时发生恢复动作的告警 |
| ECS 运行 / 关机 / 故障 / 其他 | 台 | 分别对应 ACTIVE、SHUTOFF、ERROR、其余原始状态；仅当前纳入巡检的在用 ECS |
| ECS 有指标 | 台 | 上述 ECS 中 metrics.cpu_util 非空的数量；不是全部指标的完整率 |
| CPU / 最满分区 / 数据库磁盘 / 缓存内存 Top5 | % | 按当前有效指标降序；缺失、过期或未启用不排名；不同服务分别校验来源、结果时间及采集时间 |
| 容器 24h 重启 / OOM | 条 | 按事件区间内可验证的增量计数；跨窗口且无法分摊时为 null。OOM 只有确有重启增量才计入重启；不把累计次数放在最后时刻 |
| CrashLoop / 背压 | 条 | ongoing=true 的相应类型持续事件，不限首次发生在 24h 内 |
| 台账资源 / 未分配负责人 | 个 | 11 类台账资源中 lifecycle=ACTIVE 的数量；负责人为空算未分配，不包含仅巡检作业和工作负载 |
| 近 7 天变更 | 条 | detected_at 最近 7 天且来源为 SYNC 的资源新增/变更/释放记录；手工维护和 Excel 导入不计入此同步变更卡片 |

### 健康分

1. 每资源只取未抑制活动告警中的最高严重级别：P4 95、P3 80、P2 60、P1 0。只有完整且新鲜的巡检证据、无活动告警时才计 100；台账同步时间不能代替巡检证据。
2. 单个服务分组/租户：Σ(资源分×权重)/Σ权重；核心资源权重 3，普通资源 1。没有有效巡检且没有未抑制活动告警的资源不参与评分，单独显示未知数；失联不能消除已存在的异常。
3. 平台总分：服务分组分数按该组可评分对象数再次加权，并保留 1 位小数；未知对象不进入权重。
4. 无可评分对象时返回 null，页面显示“— / 暂无有效巡检数据”；真实 0 分仍是严重异常。页面与 /metrics 的资源健康读取同一新鲜度口径。

### 任务数量与项目覆盖

任务状态按租户/项目分别判断。只有所有应采项目最近实际执行都完整成功，才汇总检查对象数和异常数；覆盖不齐返回 null。历史未知项目桶不重复加入当前项目汇总。时间与耗时来自标明的代表范围，不能当成所有项目同一时刻的快照。

## 日、周、月与台账报表

来源：`backend/app/reports/builder.py`。日报/周报/月报用起止时间定义半开区间 `[start,end)`，展示按平台配置时区。

| 指标 | 单位 | 当前口径与限制 |
| --- | --- | --- |
| 新增告警 / P1–P4 | 条 | first_seen 落在报表周期内；同一告警后续重复触发不增加新增数 |
| 已恢复 / MTTA / MTTR | 条/分钟 | 周期内新告警中已恢复、已认领的样本；均从 first_seen 开始计算，不是从认领起算恢复时长 |
| P1/P2 认领率 | % | 周期内 P1/P2 新告警中有 ack_at 的比例；分母为 0 时 null |
| 期末未恢复 | 条 | 按 end 之前最近的状态日志重建；缺少历史日志时才参考恢复时间。期末之后的关闭、重开不改写期末结果；保留数据仍有历史覆盖边界 |
| 巡检执行数 / 成功率 | 次/% | started_at 落在周期内；分母仅周期结束前已完成的 SUCCESS/PARTIAL/FAILED/TIMEOUT，SUCCESS 才计成功；SKIPPED/RUNNING 分列。无已完成执行时成功率为 null |
| 平均执行耗时 | 秒 | 上述周期内已完成实际执行的有效非负耗时，求 finished_at-started_at 平均值；跳过和运行中不参与 |
| 当前健康分 | 分 | 生成报表时读取当前总览分数；不是整个报表周期的平均分或期末历史快照 |
| 环比 | % | (本期-上期)/上期×100；上期为 0/空，或平台尚未覆盖上期时不显示，不能推断改善幅度 |
| 台账快照 / 容量 | 个/vCPU/GB | 生成时在用资源及已保存容量字段；未知容量不补 0，显示有效数量/总数量。容量是配置规模，不是实际使用率或可用余量，也不是期末历史快照 |
| 疑似闲置 | 个 | 按台账中的关机、未挂载、未绑定等启发式筛选，需核对业务归属后人工决定；平台不自动回收 |

## 作业运行五个视图

来源：`backend/app/services/job_report_service.py`。筛选、状态/来源/引擎分布、导出共用权限及条件；统计覆盖筛选全量，不限当前分页。

| 指标 | 单位 | 含义 |
| --- | --- | --- |
| 对象数 / 状态分布 | 个 | 当前选定来源与对象层级的最新快照；DGC默认父定义，MRS默认原生执行，节点/独立实例另选，禁止跨层相加 |
| 来源 / 类型 / 引擎分布 | 个 | 区分编排平台、执行平台与引擎；定义多引擎时保留列表，无引擎依据时UNKNOWN，不凭作业名或REAL_TIME猜测 |
| 未知状态 | 个 | 有快照但状态未识别/为 UNKNOWN；与 NO_DATA 分开统计 |
| 无数据 | 个 | 没有可用快照证据；不能当成功、停用或 0 |
| 活动告警 | 条 | 作业关联的活动告警计数；一个作业可以对应多条 |
| 最近更新时间 | 时间 | 当前筛选全量的最大快照更新时间；不是每个指标都在该时刻采集 |
| 节点、耗时、重启等运行指标 | 各指标原单位 | 见资源与指标指南中对应类型；保留原始状态和执行状态，缺失不补为 0 |

定义数不受近期实例窗口限制。没有近期执行的批作业仍显示，调度状态与执行状态分开；失败或未采集不当作零任务。详见[接口与分类核对](作业运行接口与分类核对_20261109.md)。

批作业 P90 仅由本轮近 24 小时完整实例清单内、同工作空间/作业的成功实例起止毫秒计算，使用 nearest-rank。默认至少 5 条有效样本，可在任务设置调整；不足时为空，真实零时长仍为 0。页面及 XLSX 同时给出窗口、有效/最低样本数和基线状态。不使用未文档化的 p90_minutes 扩展字段，也不声称完整长期基线。

## Prometheus 平台运行指标

来源：`backend/app/api/metrics.py`。数据库指标是采集时快照，多实例抓取时不能无区别相加；进程指标只代表被抓取的 API 实例，进程重启可能归零。访问权限沿用部署中的 /metrics 令牌及网络配置。

| 指标 | 类型 | 含义 |
| --- | --- | --- |
| `hcs_inspector_alarms_active` | gauge | 活动告警数（告警中 / 已认领 / 已抑制） |
| `hcs_inspector_alarms_fired_24h` | gauge | 近 24 小时新产生的告警数 |
| `hcs_inspector_http_requests_total` | counter | HTTP 请求数（本进程） |
| `hcs_inspector_info` | gauge | 平台版本 |
| `hcs_inspector_notification_oldest_pending_seconds` | gauge | 最早一条未发送通知的等待时长 |
| `hcs_inspector_notifications_24h` | gauge | 近 24 小时通知（按状态） |
| `hcs_inspector_notifications_backlog` | gauge | 待发送 / 重试中的通知 |
| `hcs_inspector_resources` | gauge | 在用资源数（按租户 / 类型 / 健康状态） |
| `hcs_inspector_silences_active` | gauge | 有效期内的静默 / 维护窗口数 |
| `hcs_inspector_sse_subscribers` | gauge | 本进程的实时推送连接数 |
| `hcs_inspector_task_api_calls` | gauge | 最近一次任务的 HCS 请求次数 |
| `hcs_inspector_task_api_errors` | gauge | 最近一次任务的 HCS 请求错误次数（含重试） |
| `hcs_inspector_task_consecutive_failures` | gauge | 任务连续失败次数 |
| `hcs_inspector_task_last_duration_seconds` | gauge | 任务最近一次执行耗时 |
| `hcs_inspector_task_last_run_timestamp_seconds` | gauge | 任务最近一次执行时间（Unix 秒） |
| `hcs_inspector_task_last_status` | gauge | 任务最近一次执行状态（值恒为 1，看 status 标签） |
| `hcs_inspector_task_last_success_timestamp_seconds` | gauge | 同任务、租户、项目最近一次完整 SUCCESS 的完成时间；没有有效成功样本不输出 |
| `hcs_inspector_worker_heartbeat_age_seconds` | gauge | 后台进程距上次心跳的秒数 |
| `hcs_inspector_http_request_duration_seconds_bucket` | histogram bucket | 本进程 HTTP 耗时累计分桶，le 单位为秒，排除 SSE 长连接 |
| `hcs_inspector_http_request_duration_seconds_sum` | histogram sum | 上述耗时总和，单位秒 |
| `hcs_inspector_http_request_duration_seconds_count` | histogram count | 上述耗时样本数 |

使用限制和实践：

- `task_*` 按任务、租户、项目分别计算，在保留的运行历史内查询，不再截取全局最近记录或固定 26 小时窗口。标签包含 tenant_id、project_ref、project_scope；旧记录项目未知时明确标 unknown，不推断归属。
- `task_last_success_timestamp_seconds` 仅使用有完成时间的 SUCCESS；PARTIAL、TIMEOUT、SKIPPED、RUNNING 均不是成功。另一个项目的成功不能恢复本项目的平台告警。
- `task_consecutive_failures` 累计 FAILED/TIMEOUT/PARTIAL；SKIPPED/RUNNING 不累加也不清零。未知项目历史不能靠已知项目成功清零。
- `task_api_calls/errors` 是最近一轮的 gauge，包含失败重试尝试；不能直接对它们使用 counter 的 rate 解释为累计 QPS。
- `http_requests_total` 才是进程内累计 counter；用 rate 观察趋势。采集 QPS 和业务应用 QPS 的边界见 QPS 文档。
- `notifications_24h` 按 created_at 最近 24h 和当前状态统计；积压应同时看 oldest_pending_seconds，重试成功不代表所有收件人均已送达。
- `silences_active` 只按未取消及起止时间筛选；周循环是否正在匹配还需检查静默规则，不能只看这个数量。
- 心跳应与任务周期、最近成功时间、积压共同判断；没有数据、没有样本和正常 0 应明确区分。
