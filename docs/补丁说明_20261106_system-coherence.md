## 发布复核修复

1. MRS 缓存保存过滤前节点清单的数量及摘要；只有本地节点完整时才复用终态实例。取消节点排除后，可以重新发现同一实例中的缺失节点。
2. 在途采集使用的范围发生变化时丢弃未提交结果；最终评估读取最新设置，不让旧快照撤销刚保存的排除规则。其他租户的范围变化不会中断当前租户。
3. CCE 健康采集批量关联同租户、同项目的台账字段，环境、业务系统、负责人和核心资源条件在查询节点前生效。
4. 新排除资源的连续命中、恢复计数及持续时间证据同时中断。恢复采集后重新累计，不与排除前的样本拼接。
5. 采集范围弹窗丢弃关闭、切租户、切类型后的迟到响应；保存绑定当前租户、资源类型和规则快照。只读用户仅查看已有规则，不调用管理权限接口。
6. 补齐 MRS/DCS 新字段指南，修复 Python 和 TypeScript 类型错误。迁移测试按历史表结构造数，覆盖升级、降级、再次升级和原数据保留；未修改原迁移文件以迎合测试。

## 迁移与备份

本包会将数据库升级至 `0020`：

- `0018` 删除 RDS、Kafka、CSS 及旧口径 MRS 作业资源、相关变更记录与部分评估状态，关闭相应活动告警。**数据清理不可由 downgrade 恢复，升级前必须保留完整备份。**
- `0019` 增加 `resource.scope_excluded`，旧数据默认仍在采集范围内。
- `0020` 仅停用符合条件的系统规则，备份原规则状态以支持降级。人工修改过的规则保留；已存在的活动告警不会仅因规则停用就被判为恢复。

原内置 PostgreSQL 的代码更新入口会先执行备份。使用外置数据库时，须先按原数据库备份流程完成备份；脚本不会替外置库备份。人工修改过的 MRS 旧字段规则需另行核对，升级不会自动覆盖。

需要回退时，必须同时恢复升级前的数据库和活动代码指针（备份中的 `code.env`），并保留旧 `releases/` 目录。仅修改镜像版本或执行 Alembic 降级不能恢复 `0018` 清理的数据；仍使用新代码执行恢复，会再次运行新迁移。

## 更新步骤

适用环境为已经安装的 ARM64 / Python 3.12 运行时，沿用本地镜像。没有新增运行依赖，不要求目标机安装 Python、Node、make、jq 或 Docker Compose V2 插件。

上传代码包及同名 `.sha256`，先在文件所在目录校验：

```bash
sha256sum -c hcs-inspector-code-20261106-system-coherence-1.tar.gz.sha256
```

然后在原部署目录执行，将 `/path/` 换成实际上传目录：

```bash
cd /data/hcs-inspector
bash deploy.sh update /path/hcs-inspector-code-20261106-system-coherence-1.tar.gz
bash deploy.sh status
```

更新入口使用独立 `docker-compose` 命令，执行校验、备份、迁移、代码切换和健康检查。代码包不包含镜像、`.env`、数据库、凭据或客户资源数据。

更新后核对：租户及采集开关保留；采集范围入口可见；MRS 作业能通过已配置 DataArts 项目查询；DCS CPU 在取得两次有效样本后显示；原有人工修改规则及未恢复告警仍需按实际状态处理。
