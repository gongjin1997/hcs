# ECS 资源监控接口核对

核对日期：2026-11-09。目标环境：HCS 8.5.1。范围：上传的 ECS、EVS、AOM PDF，华为 HCS 8.5.1 官方 API 包，华为云 CES 在线文档，以及本仓库已有采集实现。

ECS 清单负责实例、状态和分配规格；运行中的 CPU、内存、磁盘使用率需要性能数据源。对本项目，优先使用已经实现的 ManageOne 运维面性能查询。需要每个文件系统的已用、剩余容量时，还要有操作系统指标；不能用分配容量乘一个含义不明确的百分比替代。

| 要查看的内容 | 接口来源 | 能确认的边界 |
| --- | --- | --- |
| vCPU 数、内存规格、实例状态、挂载云盘 | ECS；云盘容量和挂载关系由 EVS 补充 | 分配规格，不是实际用量 |
| CPU、内存、云硬盘使用率 | ManageOne `CLOUD_VM` 性能历史 | 三个百分比；保留上游采样时间 |
| 网络吞吐、磁盘读写速率/IOPS | ManageOne 同一性能接口、不同指标 ID | 文档支持；当前 ECS provider 尚未采集这些扩展项 |
| `/`、`/data` 等分区已用/剩余 GB | 操作系统采集；可用时通过 CES Agent，或现有租户 Prometheus | 需要实际挂载点指标；ManageOne 三项百分比不能替代 |

## 上传 PDF 的逐项结论

页码写作“PDF 物理页 / 页脚印刷页”，物理页从封面开始计数。

| 文件及版本 | 已核对接口与页码 | 字段与结论 |
| --- | --- | --- |
| [ecs-api.pdf](references/ecs-api.pdf)，ECS 8.5.1，01，2025-03-30，512 页 | `GET /v1/{tenant_id}/cloudservers/{server_id}`，77 / 66；`GET /v1/{tenant_id}/cloudservers/detail`，86 / 75 | 实例状态和规格；`vcpus` 是核数，`ram` 是配置内存 MB；路径的 `tenant_id` 指云项目 ID |
| 同上 | `GET /v2.1/{tenant_id}/flavors/detail`，192 / 181；字段表 194 / 183 | 规格表的 `disk` 明确注明在本系统中无效，不能用它推算实际云盘容量或用量 |
| [evs-api2.pdf](references/evs-api2.pdf)，EVS 云块存储版 25.3.0，01，2025-03-30，271 页 | `GET /v2/{tenant_id}/volumes/detail`，96 / 90；单盘 `GET /v2/{tenant_id}/volumes/{volume_id}`，106 / 100 | `size` 是容量 GB，另有 `status`、`attachments`；没有来宾文件系统的已用容量或使用率 |
| [aom-api.pdf](references/aom-api.pdf)，AOM 2.3.0.3，01，2025-09-23，247 页 | 指标发现 `POST /v1/{project_id}/ams/metrics`，20 / 16；指标查询 `POST /v1/{project_id}/ams/metricdata`，25 / 21 | AOM 有指标查询能力；22 / 18 的 `PAAS.NODE` 明确包含主机、磁盘和文件系统指标，不能把 AOM 说成只有日志 |

ECS 文档另有两类容易误用的接口：

- 410 / 399 的 `POST /v1.0/servers/{server_id}/action` 是注册监控，属于变更操作，不是读取使用率。
- 436 / 425 起的 hypervisor 查询虽然有 `vcpus_used`、`memory_mb_used`、`local_gb_used`，对象却是宿主机，不能当成单台 ECS 的 CPU、内存、分区使用量。

官方 HCS 8.5.1 ZIP 的 ECS PDF 为 511 页，与上传件二进制不同；此次引用的 17 个关键页去空白文本一致，并非把公有云文档当成本地 Stack 版本。上传件 SHA-256 为 `5cc7822e4dfe71279264994fd3e4d550b79fca3e9005d0df95485e260e3e4048`，ZIP 成员为 `acab6d96819e0411d2dcf3d6f14c1856712dfa557bff6b4474433827ab1f399d`。已检查官方版本全文，未收录 `os-diagnostics`、`os-simple-tenant-usage` 或单 ECS CPU/内存/磁盘使用率查询；此结论限于所核对版本。

AOM 的 API 存在，不代表该环境每台 ECS 都已接入或指标维度可直接映射。按项目既定要求，所有资源仍停用 AOM，本次不把它作为接入方案。官方 ZIP 中 AOM 是 2.3.0.1／02／2025-06-25，上表查询端点在两版中均存在。上传目录未找到独立 CES 原始 PDF，因此下文 CES 的能力来自官网，单独标注适用边界。

## HCS 8.5.1：ManageOne 所需接口

来源：[华为 HCS 8.5.1 API 参考官方入口](https://support.huawei.com/carrier/docview?nid=DOC1101451954&path=PBI1-253383977/PBI1-267026473/PBI1-21431666/PBI1-253386765/PBI1-23864287)，其中《ManageOne 8.5.1 运维面API参考 03》《性能指标统一模型 01》《资源北向模型 02》。版本与原件校验值见[核对摘要](references/manageone851/README.md)。本轮重新核对了原始 DOCX/XLSX，并确认官方 ZIP 响应头 SHA-256 与本地完整归档一致。

| 用途 | 方法和路径 | 使用方式 |
| --- | --- | --- |
| 北向用户认证 | `PUT /rest/plat/smapp/v1/sessions` | `grantType=password`、`userName`、`value`，可选 `organizationName` |
| 找到 ECS 对应的监控对象 | `GET /rest/tenant-resource/v1/tenant/resources/CLOUD_VM` | `limit`、`offset` 分页；用当前项目 `projectId` 与 ECS `nativeId` 精确匹配，取得 `resId` |
| 核实监控类型 | `GET /rest/performance/v1/mgr-svc/obj-types` | 确认 `CLOUD_VM` 的对象类型 |
| 核实支持的指标 | `GET /rest/performance/v1/mgr-svc/obj-types/{obj-type-id}/indicators` | 核对指标 ID、名称、单位；适合接入验证 |
| 读取性能历史 | `POST /rest/performance/v1/data-svc/history-data/action/query` | 传对象类型、`resId` 列表、指标 ID 列表和时间范围 |

认证返回的 `accessSession` 用于 `X-Auth-Token`，非 GET 请求按北向规范携带 `roaRand`。性能接口注明接受 `IAM_OP` / `SSO` token；不能把普通租户 IAM token 或 AK/SK 直接当作运维北向凭据。资源读取需要“运维中心 > 资源实例管理 > 查询实例详情”权限，且账号须能访问目标项目和性能查询。

这里的 POST 是数据查询，PUT 用于登录认证；不涉及启停 ECS、修改云盘或终止业务会话。

`CLOUD_VM` 对象类型 ID：`562958543355904`。下表仅列统一模型中 **FusionSphere OpenStack、HCS 场景**的普通 ECS 指标（“采集指标”表第 126–134 行），不能把其他来源系统的支持情况混入。

| 指标 | 名称 | 指标 ID | 单位 |
| --- | --- | --- | --- |
| `cpuUsage` | CPU 使用率 | `562958543421441` | % |
| `memoryUsage` | 内存使用率 | `562958543486979` | % |
| `diskUsage` | 云硬盘使用率 | `562958543618052` | % |
| `nicByteIn` / `nicByteOut` | 网络流入 / 流出速率 | `562958543552537` / `562958543552538` | KB/s |
| `diskIoIn` / `diskIoOut` | 云硬盘写入 / 读出速率 | `562958543618061` / `562958543618062` | KB/s |
| `disk_read_requests_rate` / `disk_write_requests_rate` | 磁盘读 / 写操作速率 | `562958543618072` / `562958543618073` | requests/s |

该来源标记为主动上报、周期 1 分钟、不支持实时数据。因此读取历史序列中的最近有效采样；不能把“不支持实时数据”理解成没有监控。`latest-data` 接口有不建议使用的说明，且性能值字段定义了默认 `0.00`，不能仅凭成功状态码或默认值判断实例真实空闲。

三项使用率的查询体示例如下。`obj_ids` 必须替换为已关联的 ManageOne `resId`，不能填 ECS UUID：

```json
{
  "obj_type_id": 562958543355904,
  "indicator_ids": [562958543421441, 562958543486979, 562958543618052],
  "obj_ids": ["<ManageOne-resId>"],
  "interval": "MINUTE",
  "range": "LAST_5_MINUTE"
}
```

每批对象数 × 指标数不能超过 100；同时查三项时，一批最多 33 个对象。按返回序列的实际时间戳判断新鲜度，空序列保持无数据。资源 ID 重复、跨项目或无法唯一关联时不能猜测。

上例使用文档示例及当前代码的 `MINUTE`。接口还列有 `ONE_MINUTE` 等粒度，但该参数表未解释两者的具体时长差异，不能仅按名称认定查询结果一定为 60 秒一条；需核验返回的实际时间戳。模型的 1 分钟上报周期与查询聚合粒度是两回事。

模型没有给出 `diskUsage` 的挂载点、分区聚合方式或已用字节；`memoryUsage` 也没有在这些契约中明确内存分母。因此只展示原始百分比，不据此计算分区已用 GiB 或内存已用 GiB。`diskIoIn/Out` 则是 I/O 速率，与磁盘空间占用不同。

## CES：仅在现场确实提供该服务时使用

以下来自华为云公开文档，是另一条有条件的接入方式，不代表 HCS 8.5.1 局点自动具备 CES 服务或全部公有云指标。

| 用途 | 接口 | 官方文档 |
| --- | --- | --- |
| 发现实际指标及维度 | `GET /V1.0/{project_id}/metrics` | [ListMetrics](https://support.huaweicloud.com/api-ces/ces_03_0023.html) |
| 查询单指标 | `GET /V1.0/{project_id}/metric-data` | [ShowMetricData](https://support.huaweicloud.com/api-ces/ces_03_0033.html) |
| 批量读取指标 | `POST /V1.0/{project_id}/batch-query-metric-data` | [BatchListMetricData](https://support.huaweicloud.com/api-ces/ces_03_0034.html) |

| 数据 | 命名空间 / 指标 | 维度与前提 |
| --- | --- | --- |
| 基础 CPU 使用率 | `SYS.ECS / cpu_util` | `instance_id`；平台已有上报 |
| 操作系统 CPU 使用率 | `AGT.ECS / cpu_usage` | `instance_id`；Agent 已安装并正常上报 |
| 操作系统内存使用率 | `AGT.ECS / mem_usedPercent` | `instance_id`；Agent 已安装并正常上报 |
| 分区磁盘使用率 | `AGT.ECS / disk_usedPercent` | `instance_id + mount_point` |
| 分区总量、已用、剩余容量 | `AGT.ECS / disk_total、disk_used、disk_free` | 同一个实例和挂载点，单位按返回值核验 |

基础 `SYS.ECS` 也定义部分内存/磁盘指标，但支持情况依赖虚拟化类型、操作系统、VMTools；不能承诺所有 Linux KVM 实例都有。详见[基础监控指标](https://support.huaweicloud.com/usermanual-ecs/ecs_03_1002.html)。Agent 指标及要求见[操作系统监控指标](https://support.huaweicloud.com/usermanual-ecs/ecs_03_1003.html)，分区容量见[云硬盘使用情况](https://support.huaweicloud.com/evs_faq/evs_faq_0067.html)。

先发现维度，再查样本。`mount_point` 使用指标目录实际返回的值，不猜 `/data` 或把云盘 ID 当挂载点。华为的[批量查询故障说明](https://support.huaweicloud.com/trouble-ces/ces_faq_0111.html)明确说明：命名空间错误、磁盘缺少正确维度、Agent 未安装或未上报，都可能返回 HTTP 200 和空数据。

权限按现场版本核对：目录为 `ces:metrics:list`，批量查询为 `ces:metricData:list`；当前公有云单指标接口的身份策略项为 `ces:metricData:get`（别名 `ces:metricData:list`）。不同版本文档的批量上限也有差异，不把公有云最新上限写死为 HCS 的能力。

## 当前系统接入需要确认的事项

ManageOne 的 CPU、内存、云硬盘百分比来源已经在[采集代码](../backend/app/metrics/manageone.py)中实现，由独立 `ecs_metrics` 任务写入样本，ECS 状态任务读取有效样本。现场需要确认独立运维北向地址/账号、权限、项目对象关联和真实采样；文档存在接口不能证明生产已经打通。

操作入口为 **ECS 监控 → 采集策略 → 配置 ManageOne**。账号配置、来源选择、租户采集总开关、ECS 范围及性能采样开关分别生效，只保存账号不会自动开启采集。新环境继续默认关闭，不因本次文档核对改配置。

`AUTO` 当前只自动使用已配置的租户 Prometheus，不自动发现 ManageOne 或 CES。ManageOne 必须显式选择；兼容 CES 还要求全局 `INSPECTOR_HCS_CES_ENABLED` 与租户 `CES` 来源同时开启。见[选源代码](../backend/app/metrics/__init__.py)。

接口联调按以下顺序判断：

1. 登录是否成功，后续是否有 401/403。
2. 资源列表中能否唯一找到当前项目、当前 ECS 的 `resId`。
3. 三个指标是否存在，是否有最近的实际历史点。
4. 系统日志中的有效来源、对象数、调用数、样本数、失败原因与上游时间是否一致。

云平台页面有监控但本系统为空时，仍需逐项检查以上链路；不能直接判断为 ECS 没有监控能力。若要求分区详情、绝对内存用量、网络和 I/O 面板，需要在已有百分比采样之外扩展指标和展示，不能声称当前三指标已经覆盖。

本轮对照还发现以下实现边界，不能用“接口文档核对通过”代替后续联调：

- ManageOne 当前请求多传了 `projectIds`，本版历史性能接口的请求字段表未列此项；是否接受该扩展字段尚无现场证据。接口契约只要求使用已严格关联到本项目的 `obj_ids`，示例没有附加该字段。
- 兼容 CES 的[磁盘目录解析](../backend/app/metrics/ecs_readings.py)会保留上游完整维度，正常描述符包含挂载点；但代码未额外拒绝缺少 `mount_point` 的描述符。这是异常响应校验缺口，不表示所有正常请求都缺维度。
- 默认策略还可能请求 `boot_time`；ManageOne/CES 当前没有对应实现，因此即使三个百分比有值，整体诊断仍可能显示部分完成。

本次仅更新核对文档，未调整采集代码、未连接生产云服务、未改租户配置。现有测试使用合成接口响应，不能证明正式账号权限和生产采样可用。
