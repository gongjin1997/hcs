# HCS-Inspector 联调手册（局域网对接真实 HCS 8.5.1）

> 2026-11-02：`20261102-aom-disabled-1` 对所有资源（含 ECS）停用 AOM。无需补填 AOM 地址或映射；旧 AOM 选项有效为 NONE，AUTO 可继续使用已配置租户 Prometheus。租户检测与 probe 跳过 AOM，`--all` 不启用。旧记录仅供历史，详见 [AOM停用说明](AOM停用说明_20261102.md)。

目的：把平台从 Mock 环境切到局域网内的真实 HCS，核对接口与字段映射，分批放开采集，最后按清单验收。
平台对 HCS **只读**，联调过程不会对云资源做任何变更。预计 2 ~ 3 个工作日（两个租户）。

## 1 前提

- 已按《部署运维手册》完成安装，`make status` 正常，能登录控制台，SMTP 测试邮件能收到。
- 联调人员有平台 `admin` 账号、部署主机 shell 权限；HCS 侧有能协助开权限 / 查网络的局点运维。
- 采集开关建议先**全部关闭**（系统管理 → 采集开关 → 全局），录入租户、探测通过后再逐类打开。

## 2 每个租户需要准备的信息

| 项 | 示例 | 说明 |
| --- | --- | --- |
| 租户编码 / 名称 / 简称 | `tenant-a` / 租户A / A | 编码用于 `make probe TENANT=` 等命令，定好后不要再改；简称用于页面标签 |
| 认证方式 | 账号密码 或 AK/SK | 二选一 |
| IAM 地址 | `https://iam-apigateway-proxy.<region>.<domain>` | ManageOne 运营面“API 网关 / Endpoint”中查 IAM |
| 账号名（domain） | `vdc_ops` | 租户（VDC）所属的账号名 |
| IAM 用户名 / 密码 | `inspector_ro` | 账号密码方式：专用只读用户，关闭“首次登录改密”，口令有效期按局点策略 |
| Access Key / Secret Key | — | AK/SK 方式：在该只读用户下创建，SK 只在录入时出现一次 |
| 纳管项目 | Region ID、Project ID、项目名称、外部域名、环境 | 一个租户可多个项目；Project ID 在“我的凭证 → 项目列表”查 |
| DataArts 工作空间 | workspace ID 列表 | 有 DataArts 作业巡检需求时填写 |
| 指标来源 | 自动 / ManageOne（ECS）/ CES（兼容）/ Prometheus / 仅服务原生字段 | AUTO 仅选择已配置的租户 Prometheus，否则为 NONE。ManageOne 只用于 ECS 且须单独显式选择；不自动启用采集阶段、CES 或 AOM |
| Prometheus 地址 | `http://10.x.x.x:9090` | 仅租户有自建 Prometheus 时 |
| ManageOne 运维面 baseURL 与认证凭据 | 由运维人员在 ECS 监控配置中按租户维护，选 AK/SK 或运维账号密码 | 与租户 IAM 凭据分开；配置和来源选择默认关闭，只查询 CPU、内存、云硬盘使用率；须具备“查询实例详情”和性能数据读取权限 |
| Endpoint 覆盖 | `{"dcs": "dcs.region-02.example.com"}` | 个别服务域名与全局模板不同时 |
| 租户报表收件人 | 邮箱列表 | 按租户发送日报 / 周报 |

## 3 HCS 侧权限（只读）

给专用 IAM 用户（或其用户组）授予以下服务的**只读**策略（名称以局点 IAM 中的系统策略为准，一般为 `<服务> ReadOnlyAccess` / `<服务> Viewer`）：

| 服务 | 用途 | 说明 |
| --- | --- | --- |
| ECS、EVS、VPC（含子网、EIP）、ELB | 台账、ECS 巡检 | |
| GaussDB、DCS | 台账、巡检 | |
| MRS、DWS | 台账、MRS 集群巡检 | MRS 作业不调用 MRS 作业接口，见下方 DataArts |
| CCE | 集群 / 节点列表 | 另需在**每个 CCE 集群**内给该用户只读 RBAC（`view` ClusterRole 或只含 pods / events 的 get、list），用于容器事件 |
| DataArts Studio | 作业 / 实例查询；MRS 作业（作业实例详情中的 MRS 类节点） | 工作空间内授予“访客 / 只读”角色；MRS 作业巡检必须配置工作空间 |
| IAM | 查询项目（AK/SK 方式认证探测用 `GET /v3/projects`） | |

ManageOne 查询依赖独立北向认证配置及 `CLOUD_VM` 查询权限，支持按租户配置 AK/SK 或运维账号密码；首次启用后检查这两个查询接口的认证与权限结果。详见 [ManageOne 8.5.1 API 核对摘要](references/manageone851/README.md)。ECS API 的实例状态、规格和配额不包含来宾 CPU / 内存或云硬盘使用率。

## 4 网络与证书

1. 在部署主机确认 DNS：`getent hosts iam-apigateway-proxy.<region>.<domain>`（各服务 Endpoint 同理）。
   局点没有内网 DNS 时，在部署目录新建 `docker-compose.local.yml` 给后端容器加 hosts，并把它加入 `.env` 的 `COMPOSE_FILE`：

```yaml
# docker-compose.local.yml（局点自定义，升级时保留）
services:
  api: &hosts
    extra_hosts:
      - "iam-apigateway-proxy.region-01.example.com:10.1.2.3"
      - "ecs.region-01.example.com:10.1.2.4"
  scheduler: *hosts
  notifier: *hosts
  migrate: *hosts
```

```bash
# .env
COMPOSE_FILE=docker-compose.yml:docker-compose.local.yml        # HTTPS 时再加 :docker-compose.https.yml
make up
```

2. 证书：HCS API 网关多为内部 CA 签发。把 CA（PEM）放 `certs/hcs-ca.pem`，`.env` 设 `INSPECTOR_HCS_CA_FILE=/app/certs/hcs-ca.pem`，`make up`。
   仅临时排查时可用 `INSPECTOR_HCS_VERIFY=false`，联调结束必须改回。
3. 容器内连通性快速检查：

```bash
docker-compose exec api python -c "import httpx; print(httpx.get('https://iam-apigateway-proxy.region-01.example.com/v3', verify='/app/certs/hcs-ca.pem', timeout=10).status_code)"
```

4. 主机开启 NTP 并与 HCS 时间一致（AK/SK 签名会校验请求时间，偏差过大返回 401）：`timedatectl`。

## 5 录入租户与连通性测试

1. 系统管理 → 租户接入 → 新增：按第 2 章填写；凭据加密保存，之后页面只显示脱敏值，留空表示不修改。
2. 点“连通性测试”，依次检查：
   - 认证：账号密码方式强制换取一次 Token；AK/SK 方式签名调用 `GET /v3/projects`；
   - 服务：ECS / CCE / DCS / GaussDB / MRS / DataArts 列表接口各调用一次；
   - 能力：已配置的 Prometheus（查询 `up`）；CES 仅在全局兼容开关开启且租户明确选择 CES 时探测；AOM 始终跳过。CCE 按租户配置检查 Kubernetes 只读能力。
3. 结果写入租户的“能力探测”；连通不等于已取得 ECS 使用率，`up` 有返回也不能证明主机 CPU、内存或磁盘序列已接入。有效来源按租户配置选择，不根据旧探测记录自动切换。ECS 空值排查见 [ECS指标与分频采集](ECS指标与分频采集.md#cpu内存磁盘都没有数据时)。

## 6 接口探测 `make probe`

```bash
make probe-list                              # 查看租户编码
make probe TENANT=tenant-a                   # 全部接口，每个接口取 5 条样例
make probe TENANT=tenant-a ONLY=ecs,dcs LIMIT=20
```

- 每个接口输出：结果（OK / FAIL / WARN / SKIP）、耗时、返回条数与总数、**缺失的必需字段 / 可选字段**、状态类字段的**取值分布**、失败时的处理建议。
- 报告 `exports/probe-<租户>.json`：ID、IP、名称已脱敏，可直接发给开发核对；`--raw`（容器内手工执行）保留原值，只在本机看。
- 退出码：0 没有 FAIL；1 有 FAIL；2 认证失败或参数错误。采集开关已关闭的类型记为 SKIP（需要时容器内加 `--all`）。
- 结果判断：**必需字段缺失 = 台账同步 / 巡检会报错，必须先改映射**；可选字段缺失 = 对应列为空或该检查项不生效；状态取值分布里出现规则没覆盖的状态值，要补状态映射或规则。

常见失败与处理（探测报告的“建议”列会给出同样的提示）：

| 错误 | 原因 | 处理 |
| --- | --- | --- |
| `[0]` 网络不通 / 域名无法解析 | DNS、防火墙、Endpoint 写错 | `getent hosts`；补 hosts（第 4 章）；核对 `INSPECTOR_HCS_ENDPOINTS` / 租户 Endpoint 覆盖 |
| SSL 证书校验失败 | 内部 CA 未配置 | 配置 `INSPECTOR_HCS_CA_FILE` |
| `[401]` | 口令 / AK/SK / 账号名错误，Token 过期，主机时间偏差（AK/SK） | 核对凭据与 domain；同步 NTP |
| `[403]` | 缺少该服务只读权限；CCE K8s API 缺集群 RBAC | 按第 3 章授权 |
| `[404]` | 局点未部署该服务，或接口版本 / 路径不同 | 未部署：采集开关关闭该类；路径不同：反馈开发调整 |
| 返回 0 条但控制台有资源 | Project ID / Region 错误，或资源在其他项目 | 核对纳管项目 |
| 返回结构不符（items 字段名不同） | HCS 版本差异 | 反馈开发调整映射 |

| 位置 | 内容 |

| `backend/app/ledger/fetchers.py` | 11 类台账资源：接口路径、分页参数、字段 → `LedgerRecord`（名称、状态、可用区、IP、规格、vCPU、内存、容量、创建时间、attrs） |

流程：现场 `make probe` → 报告发开发 → 开发修改映射 + Mock + 测试 → 发补丁版本（如 0.4.1）→ 现场 `make upgrade V=0.4.1` → 再次 `make probe` 直到没有 FAIL。

## 8 分批放开采集

系统管理 → 采集开关（全局 + 租户覆盖，保存前会显示影响），建议顺序：

| 批次 | 打开 | 观察 |
| --- | --- | --- |
| 1 | 台账类（ECS、EVS、VPC、子网、EIP、ELB、GaussDB、DCS、MRS、DWS、CCE） | 资源台账数量与控制台一致；`ledger_sync` 运行记录 SUCCESS；没有误判“已释放” |
| 2 | ECS、DCS、GaussDB 巡检 | 状态与指标正确；告警数量合理（不刷屏） |
| 3 | DataArts 实时 / 批作业、MRS 集群 / 作业 | 作业状态映射正确；失败作业能告警 |
| 4 | CCE 容器事件 | 重启 / OOM / 背压能识别；事件量正常 |

每批打开后观察至少 1 个周期（台账 1 小时，巡检 10 分钟）；有问题先关掉该类，不影响其他。

## 9 规则与通知调优

1. 联调期间通知路由先只发给联调人员；或建一个覆盖全部告警的“维护窗口”，确认无误后再解除（解除时仍未恢复的告警会补发）。
2. 规则管理：按局点实际调整阈值、连续次数（`for_count`）、恢复回差；“期望运行”类规则（如作业非预期停止）确认资源的期望状态。
3. 通知管理：联系人 → 联系组（含组长）→ 路由（租户 / 服务 / 级别）→ 未认领升级；用“路由模拟”验证收件人。
4. 系统管理 → 巡检任务：按 HCS 接口压力调整周期（不低于各任务最小周期）；报表发送时间与收件人。
5. 系统设置 → 平台自身告警：兜底收件人填平台管理员邮箱。

## 10 验收清单

| 类别 | 验收项 |
| --- | --- |
| 接入 | 两个租户连通性测试通过；`make probe` 无 FAIL（WARN 已确认原因） |
| 台账 | 11 类资源数量与 HCS 控制台一致（抽查每类 3 条字段）；新增 / 变更 / 释放能留痕；负责人等字段导入完成 |
| 巡检 | 每个任务连续 24 小时 SUCCESS；人为制造一个可控异常（如停一台测试 ECS），能告警、认领、恢复 |
| 容器 | 测试 Pod 重启 / OOM 能在容器事件中看到并告警 |
| 通知 | 告警邮件到达；手机点“认领”成功；未认领升级到组长；静默期间不通知、解除后补发 |
| 报表 | 日报按时发送，数据与页面一致；租户报表发给租户收件人 |
| 平台 | 停掉 notifier 3 分钟产生 R-PLAT-004；`make status` / `/metrics` 正常；备份与恢复演练完成 |
| 权限 | 值班 / 只读账号只能看到授权租户；无权限操作被拒绝；操作审计可查 |

验收通过后：采集开关全部按需打开、通知路由切到正式值班组、删除联调用的静默、在《开发 Checklist》中勾选对应项。
