## 本地存储历史（已确定，前端可按此实现）

`GET /api/v1/gaussdb/instances/{resource_ref}/disk-history`

- 权限 `ledger:view`；本地查询不需要 `task:run`，不发云请求，不把当前查询写成定时样本。
- 参数 `start_at: string`、`end_at: string`（必填 ISO 8601 带时区）；`period_sec: number = 300`（整数 60–86400）。半开区间 `[start_at,end_at)`，大于 0、不超过 31 天，最多 5000 个桶。
- 返回沿用系统 `ApiResponse<T>`；data 类型如下。

```ts
interface GaussDiskHistoryPoint {
  timestamp: string // 从 start_at 开始的桶起点，非采样时间
  observed_at: string | null // 兼容字段，本地响应接收时间；失败桶为空
  collected_at: string | null // 本地响应接收时间，与 observed_at 同值，UI 显示“获取时间”
  used_gb: number | null
  total_gb: number | null
  usage_percent: number | null
}
interface GaussDiskHistoryOut {
  instance: GaussInstance // 必填；本地资源身份，供范围校验和标题展示
  source: 'GAUSSDB'
  sampling_source: 'LOCAL_COLLECTOR'
  time_basis: 'RESPONSE_RECEIVED'
  status: GaussNativeStatus
  queried_at: string
  start_at: string
  end_at: string
  period_sec: number
  points: GaussDiskHistoryPoint[]
  warning: string | null
}
```

每桶取最后一个真实采样，若本桶最后一次失败则整桶为空，不能回退到之前成功值；缺失、失败、不可信数据为空值，折线必须断开（`connectNulls:false`）。容量零只允许已用/总量，使用率为空。禁止配置量、最新台账或当前 overview 回填历史；无有效样本 `NO_DATA`，部分缺失 `PARTIAL`，完整 `AVAILABLE`。这是本地累积历史，上线前时段没有历史。`period_sec` 是查询分桶间隔，不会改变后台采集频率。

导出：`GET .../{resource_ref}/export?panel=disk-history&start_at=...&end_at=...&period_sec=300`，与 GET 同条件、同桶、同空值；仅要求 `ledger:view` + `ledger:export`。其余原生查询/导出保留 `task:run`。

**时间口径**：原生 `volume-usage` 只有容量值，没有源端采样时间。当前 `overview.disk` 新增 `time_basis: 'RESPONSE_RECEIVED' | null` 与 `collected_at: string | null`，成功/零容量响应时与兼容字段 `observed_at` 同值；失败时三个字段为空。新历史顶层固定 `time_basis='RESPONSE_RECEIVED'`，各点 `collected_at` 是当次定时 collector 的本地响应接收时间，不是查询历史时的当前时间、pipeline 的 now 或数据库快照时间。界面与 XLSX 均应称“获取时间”，不得称“源端采样时间”。报告的 `metric_series.points[].observed_at` 则确实来自报告 `data.time`，两种时间口径不能混用。

## 已完成原生巡检报告规范化

原 `GaussNativeRows.items` 保留。详情新增可选 `metric_series?: GaussMetricSeries[] | null`；详情返回数组，其他列表可为 null。

```ts
interface GaussMetricSeries {
  metric: 'cpu' | 'memory' | 'other'
  check_name: string | null
  check_item: string | null
  check_status: string | null
  name: string // indicator.name，原始指标名
  unit: string | null // 优先 metric.unit，缺失时 indicator.unit；不推测、不强制百分比
  node_name: string | null
  node_ip: string | null
  min: number | null
  max: number | null
  average: number | null
  p95: number | null
  points: { observed_at: string; value: number | null }[]
}
```

按 `metric + name + unit` 分图、按节点分线，不能把 CPU 用户态/I/O 等不同指标或不同单位合并。报告实际含内存才出现 `metric='memory'`，没有该类就显示报告未包含。`points[].observed_at` 来自原生 `data.time`（UTC 毫秒），不是 `queried_at`、报告执行时间，也不裁剪到报告执行时间；缺失值保留 null、不补零。`start_at/end_at` 仍是报告执行时间。报告指标不作为实时 CPU/内存使用率。

详情首先校验返回的 `instance_id`，再由 `status=completed` 的记录列表验证同实例同记录；详情明确返回非完成状态时拒绝。没有可验证的已完成记录返回 404，不暴露检查项。原生 `data` 同时兼容对象与对象数组；节点优先使用 `indicator.node`，缺失时沿用原生 `metrics.name`，IP 保留 `metrics.ip`，不拿实例名冒充节点。只有汇总值没有采样点的指标保留在 series 中，不伪造点。

规范化点按实际 `observed_at` 升序稳定排序，同时间戳保持原顺序、null 缺口保留。无效时间丢弃该绘图点，超出时间数组的额外数值丢弃，缺少数值的合法时间与异常数值保留 null。响应 `warning` 分别说明丢弃数量、缺值/异常数量及原始 items 保留；无效数据块和异常 min/max/average/p95 也说明。示例 indicator.unit=MB、metric.unit=GB 时，该节点 series 与 XLSX 都使用 GB，其他没有覆盖的节点才用 MB。不会用报告日期替代无效采样时间。

## 慢 SQL 与会话

- 新增导出 `panel=slow-sql-detail`，参数和详情 GET 一致：`start_at/end_at/node_ids/sql_id`；详情不向云传 threshold、不造分页参数，缓存也不因无效的 threshold 区分。微秒字段保留原生数值和单位。
- 慢 SQL 详情的响应 `start_time/finish_time`，PDF 表 4-336 的类型列与时间格式描述不一致，导出保留原生 UTC 字符串，不把它误标成请求使用的 UTC 毫秒。
- 会话先验证该实例 CN/DN 的 node/component 配对。若上游行显式返回其他 instance/node/component，整体返回安全错误，不泄漏记录。
- 原生成功查询按资源/租户/项目/认证与端点/筛选缓存 30 秒，失败短缓存；缓存服务异常返回安全 `ERROR`，不绕过缓存重复打云。导出与 GET 共用查询函数；巡检记录导出默认 limit=50，与列表一致。
