# 巡检任务执行与恢复

2026-11-10

## 执行方式

点击“立即执行”只创建持久队列记录并返回 `202`，不在 API 请求里等待云查询。每个任务、租户、项目对应一条 `task_execution` 和一条 `inspection_run`；页面按执行记录分页显示排队、阶段、计数、心跳、截止时间和错误，并在重新打开时从后端恢复。

定时和命令行入口也写入同一队列。现有 `scheduler` 内的监督器在隔离子进程里调用原采集流水线，不增加容器或运行依赖。执行租约每 30 秒到期，监督器每 5 秒续租；默认总时限 300 秒，任务可配置 15–3600 秒。子进程另设硬时限，所以个别云请求均正常返回也不能令整轮无限等待。

取消只终止本地采集进程，不调用任何云端停止、终止或重跑接口。取消请求与资源结果提交栅栏共用数据库状态检查；请求到达时未提交的当前批次会回滚。已成功提交的台账分页或清理批次按原有分批语义保留，并把整次执行记为取消/中断。

API 单独重启不会把有效租约标为中断。调度监督器重启时，仍有效的任务会保留到租约结束；过期的任务会标记 `INTERRUPTED`、释放目标并保留运行历史。总时限结束为 `TIMEOUT`，排队等待超过 30 分钟同样结束。重试会新建队列项，不复用或覆盖原结果。升级前没有执行器记录的旧 `RUNNING` 记录会在新监督器启动时一次性收敛为 `INTERRUPTED`。

## 作业接口边界

上传的 `dataartsstudio-api.pdf` 中，5.3.3 是 DataArts 作业列表，5.3.15 是 DataArts 实时作业状态：

```text
GET /v1/{project_id}/jobs?jobType=REAL_TIME&offset=0&limit=100
GET /v1/{project_id}/jobs/{job_name}/status
```

`offset` 是从 0 开始的页号；列表最多每页 1000 条，当前每页读取 100 条，并校验 `total`。工作空间通过 `workspace` 请求头传递。DataArts 实时/批任务的名单按租户、项目、工作空间保存；实时任务先读列表，再只对名单与通用采集范围交集内的作业查询 `/status`。明确的空名单不会扩展成全量监控。页面进度报告列表页数和已完成的状态查询数。

这两个 V1 接口是 DataArts 编排作业接口，不是 MRS 集群内原生执行列表。MRS 原生执行仍走既有兼容路径：

```text
GET /v2/{project_id}/clusters/{cluster_id}/job-executions
```

上传的 HCS 8.5.1 `mrs-api.pdf` 没有列出此作业接口的完整契约。它继续标记为 `unverified_hcs851_compatibility`；公有云参考不作为局点证明。默认只查已知活动状态与近期提交执行，并限制整轮页数、条数、调用数和执行时限；分页、筛选响应不一致或预算耗尽会记录覆盖缺口，不回退全历史，也不把缺口记为完整成功。MRS 查询模式、窗口、预算和单位配置见 [MRS有界采集与参数契约](MRS有界采集与参数契约_20261110.md)。

## 日志与部署

查询日志包含 `task_execution_id`、`run_id`、租户、项目、服务、阶段、页号、响应总量、已完成数和调用摘要；不记录凭据、认证头或完整云响应。排查某次长任务时，使用页面执行 ID 搜索同一组日志。

新增 Alembic 迁移 `0023`，创建执行队列表和本地取消表。代码包沿用现有运行镜像，目标环境仍只需要 `docker` 与独立 `docker-compose`：

```bash
bash deploy.sh update /path/to/hcs-inspector-code.tar.gz
```

SQLite 隔离故障演练验证了整轮超时、取消、监督器 `SIGKILL`、租约回收和新建重试；PostgreSQL 验证了迁移往返、并发入队/领取唯一性及取消与提交栅栏。它们不代替正式 HCS 局点接口与授权验证。
