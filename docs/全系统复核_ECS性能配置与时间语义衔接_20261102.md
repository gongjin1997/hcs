## 配置与响应契约

`prometheus` 配置保持单一对象：

```json
{
  "queries": {"cpu_util": "verified_cpu_percent"},
  "instance_label": "instance",
  "units": {"cpu_util": "%"},
  "timestamp_queries": {"cpu_util": "verified_source_seconds"},
  "label_filters": {"job": "verified-exporter"}
}
```

以上只是配置形状示例，不是现场已认证的表达式或标签，不会自动安装或执行。`label_filters` 为平铺的标签名到精确字符串映射；不从本地 tenant_id/project_ref 猜云端标签。查询与时间查询均只允许四个已支持指标键、最长 4096 字符，拒绝控制字符、URL；标签名校验，值非空且最长 1024 字符，最多 32 个。

单位允许 provider 既有同义词：百分比 `%/percent/percentage/百分比`；秒 `s/sec/second/seconds`。只有精确匹配内置表达式的查询可以使用内置声明单位；任何其他自定义表达式都须在新提交中显式声明单位。旧配置未声明的单位不会被回填。

新增 ECS 专用响应字段：

- `latest[metric].unit`：目前三种历史使用率指标均为 `%`。
- `latest[metric].timestamp_semantics`：`evaluation | source_sample | unknown`。
- `diagnostic.timestamp_semantics`：每个百分比指标的语义映射。
- `history.series[].timestamp_semantics`：分系列时间语义。

这些类型放在 `frontend/src/types/ecs.ts`，本轮不要求主代理改共享 `types/index.ts`。缺失新字段的旧响应，前端按 unknown 展示，不推断成 source_sample。

`evaluation` 的 FRESH 仅表示结果时间在配置窗口内，不证明 exporter 的物理采样新鲜度。`source_sample` 只表示 provider 按显式源时间查询或上游点时间解析；源时间表达式是否真正取原始序列，仍须现场核实。对聚合结果再套 timestamp 不能自动得到物理采样证明。源时间查询缺失、失败、标签不匹配等不回退到本地采集时间或新求值时间；该失败关闭行为由原 provider 负责，本轮相关 provider 回归继续通过。

## 存储与签名

不新增模型列或迁移。历史表原有 dimensions 中使用单独本地命名空间：

```json
{
  "mountpoint": "/",
  "__ecs_monitoring": {
    "version": 1,
    "timestamp_semantics": "evaluation",
    "config_signature": "摘要"
  }
}
```

不把上述本地元数据写入 `EcsReading.dimensions` 或最新快照的原始来源标签。provider 标签保持原样；历史仍按既有策略仅保留安全挂载点标签。标签中的同名 timestamp_semantics 不能冒充本地语义证据。相同源/指标/时间的重复写入保持幂等，冲突元数据不覆盖旧证据。

`config_signature` 原来已摘要整个 prometheus 对象；不另造一套签名。现在三个字段能完整到达签名函数，修改单位、源时间或标签都会使旧快照失效；配置变更时不清空或丢弃当前新映射。历史保留旧记录，不按当前配置追认其时间语义。

SQLite 内存库已执行 JSON 语义分组；PostgreSQL JSON 提取与 GROUP BY 已离线编译验证。没有访问 PostgreSQL 服务，不能把 SQL 编译检查称为 PG 实库验收。

## 主代理 / pipeline agent 交接及剩余事项

1. pipeline 已通过 `ctx.params['_collection_policy'] = policy.model_dump(mode='json')` 传完整策略；现在三个字段会自然透传，不需把字段拆散或改写。继续保留整个 prometheus 对象即可。pipeline 没有额外的 `save_readings` 调用，独立 ecs_metrics collector 已负责传 `diagnostic=result.diagnostic, signature=signature`。
2. 快照证据位于 `resource.attrs['ecs_monitoring']['latest'][metric]['timestamp_semantics']` 和独立 `unit` 字段。若严格健康/恢复门禁要求物理采样证明，不能把 evaluation/unknown 或仅有新鲜 observed_at 当成该证明。`EcsStatusCollector._metrics` 当前只传 value/observed_at/signature；如规则 facts 需要语义，可由主代理在该生产者增加 `metric_timestamp_semantics`，或由 pipeline 读取同一快照，不放进原始 dimensions。本轮没有编辑这些生产者/门禁文件。
3. 主代理报表范围：`backend/app/reports/ecs_excel.py` 仍把上游时间称“采样时间”，并只按 source 标识系列。现在同一 source 可能有不同语义系列，建议在趋势和最近结果导出增加 timestamp_semantics 列并更新旧措辞；warnings 已包含语义说明。该文件没有修改。
4. 现场仍需只读确认 PromQL 百分比/秒单位、完整标签与项目隔离、source timestamp 表达式是否取原始序列、时间查询标签完整匹配及局点 CES/Prometheus 协议。无上传契约时明确保留缺口，不自动探测、降级或切换数据源。
5. 主代理重启隔离 API 后验收实际表单保存/重载和默认求值时间提示；浏览器 QA 由主代理统一负责。本轮没有使用其管理会话，也没有连接正式环境。
