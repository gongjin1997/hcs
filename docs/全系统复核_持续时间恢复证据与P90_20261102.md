## 3. 已落地的共享修复

### 3.1 持续时间与执行身份

1. **实时节点独立计时**：每个规则指纹包含资源和 sub_object，`EvalState.data._inspection_evidence` 保存自身状态及连续观测起点；不再继承父作业 Resource.status_since。父状态变化不重置一直保持同状态的节点时长。
2. **MRS执行身份切换**：job_id 改变，即便仍 ACCEPTED，重置该执行的计时和 hits/ok_hits；Resource.status_since 同步记录新执行首次观测时刻。批实例的 instance_id 同样作为执行身份；整数/数字字符串身份统一为文本比较，避免类型差异冒充新执行。
3. **合法显式 duration 优先**：`facts.status_duration_min` 若明确提供，仅接受非 bool 的非负有限 int/float，单位分钟，允许小数；非法明确输入不退回父资源时长。无明确输入时按自身本地观测起点向下取整分钟；MRS缺job_id不猜排队时长。
4. 纯状态改变重置该状态的计时，不把两种都命中同一异常条件的状态变化强行当作条件中断；条件连续性仍由规则评估器判断。身份改变、缺采/过期及不可归属旧状态首次迁入则清连续计数。

### 3.2 明确缺采、节点缺失、旧库与隔离

- 整轮空列表、资源未返回、父资源有观测但某 check_item/sub_object 缺失，均中断受影响指纹的 hits **和** ok_hits。不会调用恢复决策来关闭旧告警。
- HCS采集失败、初始化失败、策略改变丢弃本轮数据、明确关闭采集等路径也中断本任务证据。单纯“未到执行周期”的 claim skip 不当作一次失败采样。
- `_evidence_scope` 使用稳定的 tenant_id/project_ref/task_code；无本地项目/租户ID的旧兼容上下文才用外部 account/project_id 补充隔离。不会全表清零，不动其他项目、任务或未选ECS主机。
- 老库没有新元信息时，仅依据当前目标的规则指纹、资源范围、已知子对象/告警关联恢复可证明归属的状态；不能证明归属的旧状态不猜测、不全局修改，首次有效观测时保守重建一次，之后正常累计。
- 缺采不刷新 `_last_evaluated_at`。缺采资源的 `inspection_monitoring.evaluated_at` 保留旧值，checked_rules=0；本轮其他有效检查继续正常记录，不借父项或其他任务的时效拼接子项证据。
- ECS独立 metrics 阶段不覆盖 inspection 状态证据；指标过期/配置签名变化、旧样本不重复计数等主代理逻辑保留。

### 3.3 正面恢复证据及健康租户匹配

六条默认恢复条件收紧为明确已知状态：R-DGC-RT-003/004、R-DGC-BAT-002/003、R-MRS-JOB-001/003。MRS失败告警恢复要求已知结束/成功状态加 SUCCEEDED 结果；未知字符串不能因“不等于故障态”恢复。

运行时还阻止数据缺失/未识别状态在未命中明确异常时被当作正常或恢复证据；用户自定义规则的数据库文本保留，未知源状态不能借负向恢复表达式清掉旧告警。

`refresh_health` 关联活动告警时同时匹配资源主键与实际租户；NULL只匹配NULL。三种损坏引用（1→2、1→NULL、NULL→1）先以失败回归证明会污染健康度，现均忽略；同租户及NULL→NULL仍有效。显式人工关闭后可重新得到OK/UNKNOWN，不能残留已关闭告警的缓存等级。

### 3.4 Cron、租户周期及项目运行记录

- 普通 interval 的巡检有效期=max(900秒, 实际周期×3)。Cron 使用配置时区中未来四次触发之间的三个完整间隔，避免每日任务被15分钟TTL误判、也避免手工执行恰好临近下一次触发时算出几秒周期；无效/无未来触发的cron不静默改用interval。
- ECS调用现有 `collection_policy.schedule`，显式租户inspection周期优先于全局旧task cron/interval；空观测时不再把租户 policy 覆盖回默认值。
- `policy.stale_after_sec` 仍独立约束指标样本年龄，不因状态巡检周期较长而放宽。例如inspection=1200秒得到状态TTL3600秒，显式样本TTL60秒仍为60秒。
- 正常、失败、任务skip、run_all初始化失败记录均写 target.project_ref；cleanup/global为None，不补推历史项目。0015继续down_revision=0014。

## 4. 通用运行指标完整快照

`upsert_resource` 对非ECS/DCS/Gauss资源，从资源指南 metrics 中 availability != not_collected 得到受管键集；整组Observation合并后，未输出的受管键显式写None。这样CCE过滤掉None的backpressure_min、作业失效运行时长等不能复用旧值。

- 父观测已有nodes/bad_nodes，随后子观测空metrics不会误清父值；本轮明确0保留0，缺失不会补0。
- ECS、DCS、Gauss全部跳过此通用补全逻辑，保留各自独立采样阶段、元信息及历史。
- 新 `attrs.metrics_monitoring`：observed_at=本轮本地快照写入时间（ISO8601 UTC），time_basis固定LOCAL_COLLECTION，stale_after_sec为有效巡检TTL或无上下文时900秒。不是上游采样时刻，也不生成历史样本。
- 作业报表/Excel调用统一 `current_metrics`，与 `current_health` 使用同一个读时刻。旧指标是否过期由主代理的metric_visibility判断，本分工不绕过该过滤器。

## 5. 本轮已实现的真实24h P90

### 5.1 算法与边界

1. **无新增云请求/表**：仅复用每个workspace本轮完整读取的24h instances/detail清单。分页 total 变化、缺页、重复身份或读取失败时不拿不完整列表算P90。
2. 按workspace+jobName隔离；只取status精确为success的独立instanceId。起止值须为可验证的非负整数毫秒，start>0、end>=start；缺失、bool、NaN、非法字符串或时间倒置不进入样本。原有完整清单重复ID校验仍生效。
3. 时长=(endTime-startTime)/60000分钟，样本不预先四舍五入。nearest-rank秩=ceil(0.9*n)，实现用整数式(9*n+9)//10，再取对应排序值，不用插值。
4. 任务参数 `p90_min_samples` 默认5，是**本地运维策略**而非PDF/行业阈值；仅正整数，非法值在云请求前失败。n不足时不输出facts/Observation.metrics的P90；持久化完整快照及视图保持None，不能补30或0。
5. 足量真实零时长样本允许产生真实P90=0，AVAILABLE及sample_count可区别于没有数据。历史fail/running/running-exception、其他作业/空间、executeTime、上游p90_minutes扩展都不能混入。
6. 本轮明确采用“本次24h查询返回的同名成功实例”口径，未分jobId/version/instanceType队列，也不宣称7日或完整执行历史。手工/补数/定义变更可能影响代表性，后续如要分群应使用已返回字段另定本地策略，不猜缺失字段。
