CPU、内存及磁盘使用率不能由 ECS 规格、配额或状态推算。原生候选来源已按正式 ManageOne 8.5.1 API 与性能模型复核，路径、指标 ID、认证和身份关联边界见 [ManageOne 8.5.1 核对摘要](references/manageone851/README.md)。ManageOne 支持每租户独立选择北向 AK/SK 签名或运维账号密码；凭据加密保存，不复用租户 HCS IAM 凭据。配置、指标来源和采集开关分开控制，均默认关闭。采集当前可选 ManageOne、已配置的租户 Prometheus，以及旧部署双重显式启用的 CES；AOM 仍对所有资源停用。

配额采用原生 `absolute` 字段。CPU 为 vCPU，RAM 为 MB；`-1` 表示不限额，缺失或无效值表示未知，均不显示为 0。余量仅在限额和用量均明确时计算，允许显示超额的负数。VPC 安全组、浮动 IP 的权威配额仍应查询相应服务，不用 ECS 字段冒充。社区兼容接口及默认配额不作实际配额的替代来源。

## 修复的链路问题

- 原 ECS 状态任务同时拉清单、请求指标和评估规则，频率不能独立设置。
- 原适配器只保留数值，丢失上游时间；资源的 `last_seen` 无法证明每个指标仍然新鲜。
- 原来没有 ECS 指标历史表，当前资源快照不能用于绘制真实历史。
- AOM 已全局停用，旧成功/失败能力记录和显式映射均不参与当前选源。旧 AOM 源有效为 NONE；AUTO 只使用已配置的租户 Prometheus。
- 新增独立 ManageOne 8.5.1 只读来源：按 `projectId + nativeId` 精确匹配 `resId`，查询一分钟性能历史，CPU / 内存 / 云硬盘使用率分别使用经版本核验的指标 ID。不得使用 `latest-data` 接口默认 0，不用未知或跨项目资源映射。
- 同步与采样共同修改资源 JSON 时，旧会话可能覆盖新数据。合并前重新读取并锁定资源；状态轮询不覆盖指标任务的新快照。

AOM 不再发起当前查询。已有历史样本保留其实际采样时间、来源和单位，仅供历史查看。部分指标失败不丢掉其他有效指标；非数值、非有限数、冲突维度和无依据的单位均不补成 0。ManageOne 只查询每个资源最近 5 分钟范围内的实际历史样本，使用上游毫秒时间戳；不从 ManageOne 推导 ECS 开机时间。

## 租户策略

入口：**系统管理 → 巡检任务 → ECS 任务行 → 监控配置**；ECS 监控的“采集策略”保留快捷入口。可设置全部 ECS、仅核心 ECS 或指定实例。指定实例使用本地台账记录 ID，只影响该租户的指标采集与巡检；空选表示不采集、不巡检，不回退为全量。界面按名称、IP、云端资源 ID 查找实例。

| 阶段 | 默认周期 | 执行内容 |
| --- | --- | --- |
| 台账同步 | 86400 秒 | 完整清单、规格、地址、镜像等；保留负责人、业务、核心标记等管理字段 |
| 指标采集 | 300 秒 | 仅查询选定的本地实例 ID；按来源选择 CPU、内存、磁盘及启动时间 |
| 巡检判定 | 120 秒 | 独立状态查询，并使用尚未过期的实际指标点评估告警 |
| 项目配额 | 3600 秒，默认关闭 | 按租户及项目保存原生配额快照 |

各周期可单独调整。ECS 总开关、对应全局任务、租户阶段开关必须同时允许执行。页面展示实际未执行原因。新租户明确关闭所有阶段，不继承其他租户的接入映射。

已有租户未保存新策略时，保留原任务自定义周期及 cron；新拆出的指标任务继承原启停选择。原标准 120 秒组合任务拆分后，指标默认 300 秒，自定义周期保留。保存租户策略后按该租户的周期执行。全局任务启停仍是外层控制。

调度每分钟检查到期状态，按租户、项目、资源类型及阶段保存独立时钟。成功后推进周期；失败延后 60 秒重试，不把某项目失败扩散到其他项目。原非 ECS 台账同步周期不变。手动执行可跳过到期等待，不能绕过总开关、阶段、任务或实例范围。

配额页的“刷新项目配额”是明确的手动查询，可在未启用自动配额采集时使用；仍受租户、项目启用状态、ECS 总开关和操作权限约束。进入页面或点击页头刷新只读取本地缓存。

范围支持：

- 全部已纳管实例；
- 仅核心资源，使用台账的核心标记；
- 指定实例，保存稳定的本地资源 ID。

`纳入巡检` 为关闭状态的实例仍会排除。台账清单不按监控范围裁剪，避免误判未选机器已释放。Prometheus 按同租户唯一的私网地址关联实例；跨项目重复 IP 及重复维度不猜归属。多网卡的 fixed 地址来自真实台账清单。

AOM 已全局停用：所有资源（含 ECS）均不使用旧地址、映射、可用记录或缓存恢复该来源。AUTO 忽略旧 AOM 配置，可选择已配置的租户 Prometheus；没有已配置来源时显示未接入。ManageOne 须在本租户 ECS 采集策略中配置独立北向地址和认证凭据，并显式选择指标来源；仅保存凭据不会启用来源、阶段或总开关。旧 AOM 源返回有效 NONE，保留历史数据但不当当前使用率。采样请求期间若 endpoint、账号、凭据、开关或实例范围变化，会复核配置并丢弃不再允许的结果。详见 [AOM停用说明](AOM停用说明_20261102.md) 及 [ManageOne 8.5.1 核对摘要](references/manageone851/README.md)。

## 单机趋势与告警

**ECS 监控**显示每台机器的指标值、上游采样时间、来源和过期状态。默认有效期 900 秒，可在策略中调整；新鲜度以 `observed_at` 为准，重新查询同一旧点不会刷新它的年龄。

点击实例或“查看趋势”，可切换 CPU、内存、磁盘、时间范围、均值与峰值。历史按来源分线，缺口不连线、不补零。XLSX 与已加载图表共用筛选条件，包含均值、峰值、最低值、来源和实际采样数。使用率为 0–100 的百分数，Excel 不把 72 错当作 7200%。

本地样本保留 90 天，单次查询最多 31 天、2160 个聚合时段。旧 AOM 点仅供历史查看，不生成新 AOM 样本；ManageOne 使用历史曲线的最新实际分钟点，Prometheus 和兼容 CES 保留各自真实时间。部署前未采到的数据保持空白，不用当前快照回填。ManageOne 的 `diskUsage` 是“云硬盘使用率”，页面和 Excel 不称为“最满文件系统分区”、不展示挂载点，也不把百分比换算成已用 GiB；该值不用于原有文件系统容量告警。

同源同指标同一时刻只保存一次。巡检重复读取同一物理点，不会累计多次超限或恢复条件。来源、映射变化后重新累计规则条件。关闭巡检、关闭特定指标或缩小实例范围时，受影响告警按行政 `CLOSE` 处理，保留历史；短暂查询失败不会伪造恢复。

ECS 状态接口失败时，本轮不写入推测状态，仍可用未过期的独立使用率采样判断告警；没有有效采样时不作恢复判断。Prometheus 的时间为其返回的样本/评估时间，CPU 默认仍使用 5 分钟 rate 口径。ManageOne 的云硬盘使用率仅用于展示与历史导出，不映射到最满分区告警规则。显式切换至 ManageOne 时，该租户仍活动的 ECS 磁盘分区告警写入 `CLOSE` 处理记录，标明行政关闭（非指标恢复）。

## 升级与接入

新增迁移 `0011` 创建 `ecs_metric_sample`，不修改 HCS 资源、凭据或已有采集总开关。保留独立任务的启停选择及降级配置快照；降级会删除新增指标历史表，操作前按现有流程备份数据库。

沿用现有镜像及代码更新流程，目标主机只需要 `docker` 和独立 `docker-compose`；不要求 Compose v2、宿主机 Python 或 Node，也不增加依赖和容器。

回滚到本功能以前的版本时，先暂停 ECS 全局任务；旧版本不识别新增的独立阶段与选机策略，不能依靠新策略控制旧版执行。

正式接入时先同步台账，再设置监控范围和真实指标映射，核对任务记录的序列命中率、缺失原因及采样时间。本文的接口合同和自动化测试不能替代局点实际返回值核验。

## CPU、内存、磁盘都没有数据时

先区分资源规格和运行使用量：ECS 详情中的 vCPU、RAM 及云硬盘容量是分配规格，不能计算实时 CPU、内存、文件系统使用率。ECS API 本身提供清单、状态和配额；ManageOne 8.5.1 性能模型可以查询 CPU、内存、云硬盘使用率，但只在显式配置且已选作该租户来源时请求。

| 租户配置 / 查询结果 | 当前行为 | 处理位置 |
| --- | --- | --- |
| AUTO，未配置 Prometheus 地址 | 有效来源 NONE，不自动发现监控服务，也不尝试 AOM / CES | 租户接入：确认局点实际提供的指标来源 |
| MANAGEONE 未配置或未勾选“用于 ECS 指标采集” | 有效来源 NONE，不请求 ManageOne | ECS 监控 → 采集策略 → 配置 ManageOne；确认 baseURL 与专用北向账号 |
| ManageOne 已选，但资源接口没有本项目唯一 `nativeId → resId` 映射 | 不发出历史指标查询，不猜对象 ID | 核对 `projectId`、ManageOne 项目可见范围和 ECS 原生资源 ID；同 ID 多个 `resId` 时拒绝关联 |
| ManageOne 历史查询无实际分钟点 | 显示“无有效采样”，不把 API 示例的默认 0 当真实用量 | 核对 `CLOUD_VM` 性能指标接入、只读查询权限和返回时间戳 |
| ManageOne 指标查询有返回 | CPU、内存、云硬盘使用率按百分比展示，使用上游分钟点 | 磁盘名为云硬盘使用率，不能换算已用 GiB 或当文件系统分区使用率 |
| PROMETHEUS，但地址为空 | 不发起指标请求 | 租户接入：填写已存在且已有主机采样的监控地址 |
| NONE（仅服务原生字段） | ECS 清单、状态及配额可查，使用率无数据 | 租户接入：若需要使用率，接入已核实的指标来源 |
| 旧 AOM | 仍停用，不会自动迁移到其他来源 | 核实已有监控服务，不能靠补填 AOM 地址恢复 |
| CES，但全局兼容开关关闭 | 不发起 CES 请求 | 先核对局点的 CES 文档、端点、权限；不要仅为消除空值而启用兼容接口 |
| Prometheus 已配置，但没有可唯一匹配的私网 IP | 不发起该批指标查询 | 先同步台账，检查地址、跨项目重复 IP 和实例选择范围 |
| 查询成功但未匹配序列 | 无样本，不补零 | 核对主机采集端、查询表达式、实例标签及私网 IP |
| 返回的点全部过期 | 保留历史，当前值显示过期 | 检查监控端采样时间、采集周期和有效期 |

上传的 `hcs-inspector-1106.log` 中，2026-11-06 01:20:09 UTC 的 ECS 使用率任务（运行号 4537）记录了 201 台资源、0 次上游调用，却标为 SUCCESS。这里的资源数来自实例观测记录，不能证明取得了使用率。旧日志没有记录指标来源及缺失原因，因此仅凭该条记录还不能区分“没有指标源”和“没有可匹配的 IP”。

2026-11-07 修复后，已启用且有选定实例的指标任务，如果没有来源、全部未匹配序列、没有数据或全部样本过期，将记为 PARTIAL，错误摘要说明具体原因。部分实例有新鲜样本、部分没有时仍记录实际覆盖情况，不仅因关机实例缺少样本而触发任务失败；真正的查询错误仍记为 PARTIAL。已关闭或没有选定实例的范围不因此变成采集故障。原有有效采样和状态采集保留；不生成零值，也不自动开启来源或采集开关。持续 PARTIAL 沿用现有重试及平台任务告警规则，配置暂未就绪时可关闭该租户的指标阶段，独立状态巡检继续运行。

任务运行记录显示实际采样数；`task_finished` 日志补充 `metrics_source`、`metrics_status`、`metrics_reasons`、`metrics_requested_resources`、`with_metrics`、`sample_points`、`metrics_fresh_points`、`metrics_stale_points`、`metrics_rejected_points`。`with_metrics` 表示有实际采样的实例数，包含过期历史点；是否能作为当前值要看新鲜度。日志不输出监控地址、查询表达式、原始序列或凭据。

当前产品级根因已明确：ECS 清单 API 不返回 CPU / 内存 / 磁盘实际使用量；在此前的实现中，仅支持租户 Prometheus 和旧 CES，正式环境未配置这些来源时，任务没有发出任何指标查询，所以指标一直为空。随后又修复了“零调用/零样本仍显示 SUCCESS”的任务诊断，并接入经 HCS 8.5.1 文档核验的 ManageOne 独立查询。你提供的 `hcs-inspector-1106.log` 运行 4537 记录 201 台、0 次上游调用、SUCCESS，但未记来源，不能用来断言正式租户当前一定未配置 ManageOne，也不能确认生产权限和实际返回；ManageOne 源目前需要在该租户明确配置后才会发出请求。

现场确认当前运行状态时，只需提供租户的指标来源选项、ManageOne 的“已启用/已选择”状态（或 Prometheus 地址是否已配置）以及该次任务诊断字段，无需发送地址或凭据。若未产生采样，再给出脱敏的原因字段和对象/样本计数即可。ManageOne 租户资源属性的 `ownerType` / `ownerId` 取值需现网确认；程序只确认两字段存在、项目和原生实例 ID 匹配，不猜测其值等于性能模型中的 `FusionSphere OpenStack`。本次未连接生产环境，生产 endpoint、权限、来源字段和真实采样仍待部署后验证。
