## 查询模式

| query_mode | 查询集合 | 覆盖含义 |
|---|---|---|
| active_and_recent（默认） | 依次按五个已知活动状态分别查，不带提交时间；另查近期窗口 | 活动执行与近期提交执行的并集，能发现早已提交、仍运行的Flink |
| active_only | 仅五个活动状态，不带时间窗 | 不覆盖已终止执行 |
| recent_only | 仅提交时间窗 | 可能遗漏窗外提交、尚在运行的执行，需显式选择 |
| all_history | 显式无状态/时间筛选 | 仍受整轮预算约束；大历史量不会因此获得无限扫描授权 |

默认近期窗口 `[本轮开始UTC毫秒-24h, 本轮开始UTC毫秒]`，同轮所有集群/分页复用。`submitted_window_hours` 只调整近期分支；也可指定 `submitted_time_begin`、可选 `submitted_time_end`（默认本轮开始时间），二者与小时窗口互斥。active_only/all_history 不接受显式窗口设置。

每个集群查询前先应用已配置 cluster 包含/排除范围，排除集群不发执行请求；job/id 范围在响应验证后应用。按 `(cluster_id, job_id)` 去重，不按名称合并；跨分支重复执行取后查询的响应，防止保留较旧状态。同一个 job_id 在不同集群仍是不同执行。同一分支分页内重复 ID 仍是分页不完整，不能当正常去重。

## 参数 schema 与前端/API 交接

直接复用 `backend/app/collectors/mrs_params.py`：

```python
from app.collectors.mrs_params import mrs_parameter_schema, validate_mrs_params

schema = mrs_parameter_schema("mrs_job_status")  # 或 dgc_mrs_node_status，返回独立副本
native_params = validate_mrs_params("mrs_job_status", submitted_fields)
```

schema 原数据为 catalog 的 `MRS_TASK_PARAM_SCHEMAS`。严格校验只允许 schema 中字段，不允许 endpoint、headers、任意 filter、凭据或公共内部参数。校验错误抛 `HcsError(code="LOCAL.INVALID_CONFIG")`，API 层需映射为项目现有参数错误。默认填充后返回值可重复验证/持久化；编辑模式切换时应替换 MRS 参数子集，删除不再适用的旧窗口字段，不应把表单隐藏字段无条件补默认后传入 all_history/active_only。采集器以 `strict=False` 读取旧任务，忽略公共/旧 DataArts 参数，避免误将 window_hours 等当原生授权。

### 任务 API 最终对接约定（已确认稳定）

`TaskPatch.mrs_options` 仅向 `mrs_job_status` 开放，含义为**完整配置替换**，不是合并更新；仅补齐所选模式适用的默认值。字段未提供则不修改原生配置；提供空对象 `{}` 则重置为 active_and_recent/24h 与其余默认预算。null不代表重置，不应当作空对象传入helper；若TaskPatch允许null，应沿用API明确定义的未提供/拒绝语义。strict校验在任何持久化修改前执行，错误时不改变旧params。

保存时先取得 `fields = set(mrs_parameter_schema("mrs_job_status")["properties"])`，删除旧 `InspectionTask.params` 中所有这些字段，再平铺写入 `validate_mrs_params("mrs_job_status", mrs_options, strict=True)` 的返回值。不能先与旧原生参数合并，也不能只update返回值，否则模式切换会遗留显式时间窗。`timeout_sec`、内部非MRS项及旧非原生 `window_hours/max_details` 均不在这个字段集合中，原样保留；采集器继续忽略旧节点项。

返回给任务页的params只取原生白名单字段，不借此返回内部项；timeout_sec按任务API已有的独立公开约定返回。active_only/all_history的规范化返回不含任何提交窗口字段；从这些模式切回空配置则恢复active_and_recent/24h。UI模式切换须从提交对象中删除不适用的隐藏窗口字段；helper不会静默丢弃调用方显式传入的矛盾字段，会报参数错误。已新增专项回归验证替换、默认重置、窗口删除、内部项保留及响应白名单。

| 参数 | 默认 | 限制 |
|---|---|---|
| query_mode | active_and_recent | 上表四种枚举 |
| submitted_window_hours | 24 | 有限数值，0 < 小时 ≤ 744；不接受 bool/数字字符串 |
| submitted_time_begin/end | 未设置 | 有效 UTC 毫秒整数，起点必需、终点不早于起点 |
| page_size | 100 | 整数1..1000，保留原兼容配置上限，不声称官方保证1000 |
| max_pages | 200 | 整数1..200，**整轮所有执行查询共享** |
| max_items | 20000 | 整数1..20000，整轮返回执行条数，跨查询重复也计入 |
| max_calls | 400 | 整数1..400，逻辑GET次数和底层请求尝试分别受此上限约束；含集群发现/失败，底层含重试及纳入共享额度的IAM鉴权 |
| max_clusters | 1000 | 整数1..20000，范围内集群数，超出时不查询执行 |
| job_offset_mode | page | page / offset，均从1起 |
| elapsed_time_unit | null | null / milliseconds / seconds，仅经局点确认后设置 |

### `LOCAL.MRS_BUDGET` 处理

原默认值为整轮2000条、24页、30次调用。一个集群的近期执行超过2000条，或多个集群/活动查询累计占用额度后，近期分支可能在第一页就因总数超过剩余额度而停止；这不代表已经读取到上限，也不是MRS云端返回的错误。

现默认值调整为20000条、200页、400次调用；每页仍为100条，查询范围、24小时窗口、整轮超时和共享限速不变。三项上限分别生效，空页也计页数，重试/鉴权也占底层请求额度，不保证所有组合都能读取满20000条。

**已保存的显式参数不会被升级覆盖。** 在“巡检任务 → MRS 原生作业执行 → 编辑”检查并分别设置整轮条数20000、页数200、调用400，保留原查询模式、窗口及采集范围，然后保存并重新执行。只修改条数可能随后触发旧页数/调用上限。不要对已有自定义窗口的任务直接发送 `mrs_options={}`，该操作会重置全部MRS参数。

报错现在包含上限、实际已用额度；已读到总数时还包含本查询总数、完成当前查询所需的整轮最低条数。后者包含前面查询/集群的实际返回数，不重复累计本查询已读页，也不预测尚未查询的集群。结构化日志 `mrs_budget_exceeded` 和 `mrs_jobs.budget_exceeded` 保存同一组数值及集群/查询上下文。若所需条数仍超过20000，应按业务要求明确调整监控范围或近期窗口，不自动缩窗或把未采集部分当作成功。

## 完整性与进度

每个查询分支先完整验证分页，再加入执行并集：总数字段必需、总数不变、不得提前空页、不得重复页/ID、不得返回超过请求页大小。实际读取条数按返回值记账；同一查询的请求页大小保持固定，不能因剩余预算变化改变页码对应的起点。预算不足时不发下一请求，并记录错误。失败分支不输出部分分页；已完整验证的其他分支仍可输出，但整轮必须带缺口，不能标成完整SUCCESS。

逐行验证 `job_state` 与请求一致、近期响应 `submitted_time` 为可解析毫秒且落在请求窗口。服务忽略筛选、返回未知/缺失提交时间等，记录 `LOCAL.MRS_FILTER_UNCONFIRMED`，`coverage=unconfirmed`、`coverage_complete=false`，写入 `ctx.errors` 供执行器记为PARTIAL/FAILED。不会在本地静默过滤掉矛盾行后假称完整，也不改发全历史。空列表、相容的返回行只能证明响应一致，不能证明服务绝无遗漏：统计保留 `filter_contract=public_sdk_not_site_verified` 与 `filter_evidence=response_consistency_only_no_proof_of_non_omission`。`coverage=response_validated` 表示已验证请求集合完成，不能宣传为 HCS 局点筛选能力认证。

`ctx.stats.mrs_jobs` 记录 query_mode、budgets、calls、pages、items_returned、duplicates、clusters_completed、queries_planned/completed、各分支filters/total/pages/items/coverage与总覆盖判定。calls 是逻辑GET尝试数，失败也计数；另复用已有 `request_budget(attempts=max_calls, seconds=inf)`，使 HcsClient 底层重试/鉴权不能重置整轮请求尝试额度，真实wire调用数仍由客户端统计。inf只表示不设采集器自己的硬deadline，现有上层请求deadline会按更早值继承。硬超时/取消/租约失效应由执行器的 `ctx.progress` 抛其专用异常（例如 TimeoutError），采集器不吞掉非 HcsError 控制异常。

进度接口为主代理约定的 `ctx.progress(phase, *, current=None, total=None, unit=None, message=None, **details)`：集群发现每页前后、原生每页前后、每分支读完和每100条执行处理边界、DataArts实例每页与详情每批均报告真实数量。只在能确知的范围提供 total（例如范围内集群、已取得的待处理执行/实例数），不构造百分比。MRS helper总会保存mrs_progress本地统计，即使未托管RunContext的progress为空操作也不丢失真实计数；尚无progress方法时另写结构化日志。

ASGI Mock的job-executions路由已按新增授权修复：单值job_state与提交时间上下界先过滤，再计算total_record并分页；拒绝小写/逗号多状态/未知状态语法。默认active_and_recent的真实ASGI链路已验证完整覆盖；另有反例主动移除job_state，验证忽略筛选仍报告覆盖不可确认。没有给采集器添加mock特例。
