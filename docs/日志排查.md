# 日志排查与离线诊断

本指南针对本机和纯内网定位问题。日志关联 ID 不是登录令牌，不能用于认证；请勿把 Token、口令、DSN、AK/SK、真实请求体或配置文件放进排查材料。

## 1. 三种日志落点

| 场景 | 保存位置与轮转 | 注意事项 |
| --- | --- | --- |
| LAN 脚本管理的服务 | `.runtime/lan/logs/<service>.jsonl`；单文件 10 MiB，最多 5 份备份 `.1` 至 `.5` | 独立监督器捕获 stdout 与 stderr，包括 Python import、uvicorn 启动前的错误；不靠后台服务重新打开 stdout |
| Docker Compose | 容器 stdout/stderr；`json-file`，`max-size=50m`、`max-file=5` | 保留已有生产上限，演示的 Mock HCS/Mailpit 也显式限额；不是永久历史仓库 |
| 后端原生文件（单进程），可选 | `INSPECTOR_LOG_DIR` 指定目录，按 service 写 JSONL | 默认不开文件，仍输出 stdout；默认单文件 10 MiB、备份 5 份，目录必须可写且私有 |

后端 JSON 时间戳为 UTC（Z）；nginx 时间戳含时区偏移。与页面/调度时间对照时先统一时区。

后端公开设置：`log_level=INFO`、`log_dir=None`、`log_max_bytes=10485760`、`log_backup_count=5`、`log_slow_request_ms=2000`。环境变量沿用 `INSPECTOR_` 前缀。DEBUG 仅在必要时短期开启，结束后恢复 INFO。

LAN 启动器移除子进程继承的 `INSPECTOR_LOG_DIR`，同时设置 `INSPECTOR_ENV_FILE=''`：核心只输出结构化标准流，由监督器唯一持久化，避免同一条日志同时写两套文件。它不读取真实 `.env`。生产若选 Docker stdout 留存，通常保持 `log_dir` 为空；如确需原生文件，应单独安排可写持久目录及容量，避免误以为两套日志只占一份空间。

**旧进程不会自动切换日志 fd。** 升级时正常重启应用进程后，确认新 JSONL 文件产生；旧的 `.runtime/lan/*.log` 不会被移动、截断或删除。既有 Docker 容器的日志参数也需在获准重新创建容器后生效；不要为日志调整删除数据卷。

## 2. 用关联 ID 串起一次请求

1. 在浏览器开发工具的响应头中取得 `X-Request-Id`。后端会校验客户端候选值，不合法时重新生成并返回。
2. API 访问日志与业务日志通过 `request_id` 关联；长耗时请求还可结合 `status`、`cost_ms` 和服务名查看。
3. nginx access JSON 记录后端响应里的关联 ID，不将客户端原始请求头当作可信 ID。静态文件、重定向或未到后端的请求可能没有关联 ID，这是预期情况。
4. nginx 的 `request_time_sec` / `upstream_time_sec` 单位是**秒**；后端的 `cost_ms` 单位是**毫秒**，不要直接比较数值。

nginx 使用 JSON escape 格式；不记录 query、Authorization、Cookie、Referer、User-Agent 或请求体。`/api/v1/mail-actions/<token>` 和 `/m/action/<token>` 的 token 段经 map 替换为 `[REDACTED]`。后端 `safe_path` 也会清理 query 和邮件链接 token。SPA 内部回退可能将 access path 记为 `/index.html`。

nginx 原生 error log 不能使用 access 的自定义 JSON 格式，某些错误可能附带请求行；仅在本机受控查看，不直接转发。下面的诊断工具不会导出它的非 JSON 原文。

## 3. 一键离线概况

从仓库根目录执行，仅检查**显式指定的专用日志目录**：

```bash
# 在仓库根目录执行；使用绝对路径，不含 ..
INSPECTOR_ENV_FILE='' backend/.venv/bin/python -m app.tools.diagnostics overview \
  --log-dir "$PWD/.runtime/lan/logs"
```

结果包含应用/Python/系统类型版本、候选文件数量、读取与输出字节数、合法结构化记录数、非 JSON/超长行数量及截断标志。**它不连接 HTTP、数据库、Redis、SMTP 或 Docker，不调用 `status`，也不检查服务健康。** “没有日志”或“缺少记录”不能解释为健康/成功。

此命令不读取 `.env`、LAN `config.json`/`processes.json`、证书、备份、数据库文件、Git 历史、环境变量内容、Docker inspect 或容器环境。

## 4. 一键生成本机诊断包

LAN 的快捷入口：

```bash
make diagnostics
# 等价：python3 scripts/lan.py diagnostics
```

该入口不调用 LAN start/stop/status，也不读取 LAN 凭据配置；输出到 `.runtime/lan/diagnostics/`。

也可显式指定日志目录和输出目录：

```bash
# 在仓库根目录执行
INSPECTOR_ENV_FILE='' backend/.venv/bin/python -m app.tools.diagnostics bundle \
  --log-dir "$PWD/.runtime/lan/logs" \
  --output-dir "$PWD/.runtime/lan/diagnostics"
```

包中只有 `manifest.json` 与 `logs/` 下经过筛选脱敏的 JSONL。不会递归把整个运行目录打包；归档成员不含绝对路径、`..`、symlink 或原始配置。新建输出目录权限为 `0700`，归档为 `0600`，不会覆盖已有同名文件。已有输出目录必须由当前用户拥有且为 `0700`，否则拒绝；不会擅自修改共享目录权限。

### 默认安全边界

- 只接受显式日志目录，逐路径组件使用目录 fd 与 `O_NOFOLLOW`；拒绝含 `..` 的路径、目录 symlink、日志 symlink、硬链接、FIFO、目录和设备文件。
- 文件名限制为已知服务的 `.jsonl` / `.log` 及数字轮转后缀，例如 `api.jsonl.1`；不收集 `.env`、配置、数据库和任意名称文件。
- 默认每文件最多读末尾 **1 MiB**，累计读/输出日志最多 **8 MiB**，最多 **30 个文件**，单行最多 **64 KiB**。优先各服务当前文件，再收轮转文件。
- 大文件只读取有界 tail，并丢弃 tail 开头的半行；不从头扫描 GB 级日志。总量受限时可能缺少更早记录，应结合 manifest 判断。
- 默认**跳过非 JSON 行，只记数量**。即使某段自由文本看起来像错误，也不能证明不含凭据或客户数据，因此不直接打包。
- JSON 仍调用共享 `sanitize_log` / `safe_path`。只导出请求/云端关联 ID、数字 tenant/project/run/user ID、时间、级别、任务、服务、路径、状态、调用/等待计数、错误类型/代码，规则/通知/报表标识、各云服务调用/错误/等待计数，以及从堆栈或启动stderr提取的文件名/函数/行号等允许字段；`msg`/`message`、异常堆栈原文、请求体、headers、payload、任意扩展字段不导出。从有界 traceback 中最多提取最后 32 个技术 `frames`（Python 文件 basename、函数名、行数）与 `exception_type`，不包含绝对路径、源码行或异常消息；无法安全识别时省略。原始 JSON 日志仍留在本机供有权限人员按需检查。
- “完成脱敏”不等于可以任意公开。对外或跨团队分享前，仍应检查包中路径、事件代码和关联信息是否符合本单位数据管理要求。

允许收集的服务名：`api`、`scheduler`、`notifier`、`mock`、`web`、`startup`、`migrate`、`bootstrap`、`run_once`、`build`、`containers`、`stop`、`nginx-access`、`nginx-error`。Docker 日志不被自动读取；如确需归档，应由授权操作人先将所需的结构化日志放到一个独立目录，再显式指定该目录，不能把 Docker 数据根目录交给此工具。

### 调整预算

```bash
INSPECTOR_ENV_FILE='' backend/.venv/bin/python -m app.tools.diagnostics bundle \
  --log-dir "$PWD/.runtime/lan/logs" --output-dir "$PWD/.runtime/lan/diagnostics" \
  --max-file-bytes 524288 --max-total-bytes 4194304 --max-files 20
```

单文件硬上限 10 MiB，总量硬上限 50 MiB，文件数 1–100；工具会拒绝无效预算。上限指日志内容的读取/输出预算，归档还含少量 manifest 与 tar 元数据，不应把它当作压缩文件严格字节上限。目录不存在、权限不足、含 symlink 或限制无效会返回非零，错误不回显源内容。

## 5. 常见排查顺序

| 现象 | 先看什么 | 不要误判 |
| --- | --- | --- |
| API 500 | 响应关联 ID → API JSONL 的 status/error_type → 本机受控查看对应错误上下文 | 不把请求体、令牌或原始 SQL 参数贴入工单 |
| 页面慢 | nginx 请求秒数与 upstream 秒数、后端 cost_ms、导入/报表任务时间 | SSE 长连接持续时间不是普通接口响应延迟 |
| 服务启动失败 | 对应 service JSONL 的早期 stderr；迁移看 migrate/bootstrap；构建看 build | 尚未生成 API 业务日志不等于没有启动错误 |
| 后台未执行 | scheduler/notifier 日志与实际任务运行记录；本工具只离线汇总文件 | 不能用“诊断包生成成功”断言后台健康 |
| 日志突然变少 | 文件轮转序号、manifest 的截断/省略数量、剩余磁盘空间 | 非 JSON 被跳过是安全策略，不是采集成功记录为 0 |
| 关联 ID 对不上 | 确认复制的是响应头；区分静态响应与上游响应；比对服务/时间单位 | 不把客户端随意填写的 header 当作可信追踪证据 |

采集问题按 `run_id` 查 `task_started` / `task_finished`、`collection_partial_failure` 和 `collection_data_unavailable`。MRS/CCE 的数据缺口日志带固定 `reason`。从 2026-11-06 的 CCE 修正起，事件计数/时间校验及跨窗口问题仅记录 INFO，不进入任务错误摘要或平台告警；运行记录 `stats.event_data_diagnostics` 按原因计数，`event_window_unknown_checks` / `event_window_unknown_events` 汇总窗口计数缺口。`phase=event_validation` 的 `affected_count` 表示跳过的输入事件数；`phase=event_window_count` 的 `affected_count` 表示受影响的计数检查数，`unknown_event_count` 表示该窗口无法精确计数的事件条目数（同一事件可能参与不同检查，不是去重事件总量）。具体原因见《CCE事件计数与告警处理_20261106》。

台账同步另看 `ledger_sync_started`、每类资源的 `ledger_snapshot_completed` 或 `ledger_snapshot_failed`：`phase` 区分接口拉取与数据库应用，记录数、上游调用数、变更数和耗时可判断失败发生在哪一段。数据库错误只记录 SQLSTATE、表/字段、可识别的列宽和输入字符串长度，不包含值、语句或参数；上游失败记录状态码、错误码、网络原因和重试性，不记录响应正文。离线诊断包会保留这些受限字段。

## 6. 容量与压力验收

- 请求日志单条最多 **64 KiB**，大扩展字段可省略，优先保留异常与关联字段；健康探测、空通知轮询及 SSE 心跳不刷 INFO。正常云请求使用 DEBUG 明细，INFO 保留每轮任务/服务调用汇总，失败保留状态、错误码、耗时、重试次数和定位栈。
- 主日志 formatter 本机微测：10,000 条常规结构化记录约 **552 ms**（约 **55 μs/条**）；1 MiB 无分隔长字符串截断后脱敏约 **2.4 ms**。这是当前机器的单次测量，不代表生产吞吐保证；测量不访问云、数据库或外网。
- 真实独立 Redis + 两个子进程实测：8 次合成请求共同遵守 **4 QPS** 平滑间隔，在途不超过 **2**；不同 limiter 实例共享冷却窗口；另用 ECS/DCS 两服务、两子进程、8次 Mock transport 发送实测总闸 4 QPS，最短开始间隔 **251.32 ms**，在途峰值 **2**。Redis 失效时 HCS transport 实际发送数为 **0**，不会突然放开流量。
- LAN 单服务当前+5份备份的文件内容上限约 **60 MiB**；5个常驻服务合计约 **300 MiB**，此外构建/迁移等单次服务各有独立预算。旧版文件不被删除，不计入新轮转上限；磁盘剩余空间仍需运维监控。
- LAN 监督器在正常进程组停止时排空退出日志；磁盘写入故障会继续排空业务输出、限频重试，恢复后记录省略条数，避免日志 I/O 故障终止业务。写不进去期间无法保证日志不丢失。

### 云请求保护

全云服务共用总闸，默认 **10 QPS / 4 在途请求**，IAM 与 Prometheus 也计入；再叠加各服务自己的额度。总闸可用 INSPECTOR_HCS_TOTAL_QPS / INSPECTOR_HCS_TOTAL_CONCURRENCY 设置，修改保护上限需重启相关进程。每云服务的 QPS 设置仍由系统设置控制；默认多数服务 5 QPS，CES/CCE Kubernetes API 为 10 QPS。共享平滑限速不因新建客户端/租户/任务重新补满令牌，配置 Redis 时跨 API/worker 进程共享，默认每服务最多 2 个在途请求；没有配置 Redis 时只保证单进程共享。重试总次数包含首次发送及 401 刷新后的发送，默认最多 3 次，尊重 Retry-After 并共享冷却，只有已登记只读查询允许发送，禁止自动跟随重定向。

DCS 历史仍按 10 实例一批、每天一段，分别查询平均值和峰值：20 实例 × 31 天的首次完整读取最多 **124 次 CES 业务查询**（不含 IAM 与失败重试）。请求另有 384 次尝试/60 秒预算；同 scope、配置、资源和时间范围在 30 秒内复用原始数据，页面/导出和不同聚合粒度可共享，同一并发查询只执行一个 loader。权限、停用状态在缓存前重新检查，错误不缓存为正常数据。

缓存单结果解压上限 32 MiB；单进程压缩缓存总量上限 64 MiB、64条，Redis共享缓存总量上限64 MiB、128条，短时 TTL。IAM 令牌在进程内按租户/项目/凭据/端点隔离复用并合并刷新；各进程之间仍可能各取一次，不共享明文凭据到诊断包。

以上为客户端约束和隔离测试结果。真实 HCS 的网关配额、云监控查询开销与网络时延尚未接入验证，不能据此承诺绝对“零压力”；首次上线应按该局点配额保守配置，结合每轮 `api_calls` / `rate_limit_ms` / `upstream_errors` 调整周期与 QPS，不通过压测真实云平台确认上限。

## 8. 浏览器错误定位

普通接口错误和 silent 调用的内嵌错误提示均显示关联编号，原始业务文案保留在 ApiError.rawMessage；取消请求不报错；Vue/window/unhandledrejection 只保留技术类别、已加载脚本文件名与行列，不采集业务消息、页面内容、localStorage、口令或邮件链接令牌。已登录时同源上报本机 API；同故障一分钟去重、总量每分钟最多10条，服务端另做按用户去重/限量与8KiB请求体限制。离线和未登录时保留安全的本机控制台记录，不重试、不调用云。

## 9. 现场业务服务 DNS / TCP / TLS 核对

将 `deploy/scripts/network-check.sh`、`network-check.py` 放在同一目录，在目标机运行：

```bash
bash network-check.sh --tenant 实际租户编号 --services all > network-services.json
# 多项目时可指定该租户下启用的项目记录编号：
bash network-check.sh --tenant 实际租户编号 --services ecs,cce,dcs --project-ref 实际项目记录编号
```

默认部署目录 `/data/hcs-inspector`，可用 `--deploy-dir` 指定其他绝对路径。脚本复用部署目录的独立 `docker-compose` 入口，通过 API 容器的标准输入执行 Python；宿主机不需要 Python、Node、jq 或 Compose v2 插件。

`all` 检查 IAM、ECS、CCE、DCS、GaussDB、MRS、DataArts、EVS、VPC、ELB、DWS（EIP 复用 VPC 地址）。结果逐项显示实际地址、配置来源和 DNS/TCP/TLS/HTTP 阶段；同地址只检查一次。只选取端点、区域和项目配置信息，不查询 AK/SK/密码，不发送认证头，不跟随重定向，不修改配置。HTTP 401/403 表示链路可达，不能据此认定认证或权限正常。

业务日志新增固定 `network_reason`、`retryable`。域名不存在、证书校验失败、访问权限被拒绝须先修配置，不自动重试；临时 DNS 故障保留重试。正式配置不自动删除 `console.` 或截取资源空间名称，应按底座导出表核对 `region0_id`、`external_global_domain_name`，或填写实际服务 Endpoint 覆盖。

构建会生成隐藏 source map，JavaScript 不发布 sourceMappingURL；nginx 与 LAN preview 禁止通过 HTTP 读取 .map。需要定位压缩文件行列时在运维机使用本机 dist/assets/*.map 和支持 source map 的开发工具；不要把 map、原始源文件或页面内容加入诊断包。

### 退出与重启

API 在 LAN/开发启动命令中设置8秒退出等待，Docker默认 API_GRACEFUL_TIMEOUT=8。超过等待时限的长连接/未完成请求会取消，随后记录 service.stopped 与监督器 process.exited，避免 SSE 长连接无限阻塞退出。实测保持一条真实 SSE 连接时8.27秒退出并恢复readyz。若调整Docker等待时限，应同时保证Compose stop_grace_period大于它，留出清理时间。

计划SIGTERM保留原始exit_code=-15、exit_signal=SIGTERM，并标记expected_shutdown=true、INFO；不是运行崩溃。真实非预期退出仍为ERROR。停止LAN请使用make lan-stop，按该项目记录的进程组停止；不要仅杀监督器PID。
