# HCS-Inspector 开发文档（v0.4）

面向后续接手开发的同学：环境搭建、代码结构、编码约定、常见开发任务的步骤、测试与发版。架构背景见《架构文档》，部署见《部署运维手册》。

## 1 开发环境

## 3 后端约定

### 3.1 分层

`api/v1/*`（参数校验、权限、审计、组装响应）→ `services/*`、`ledger/*`、`notify/*`、`reports/*`（业务逻辑，接收 `Session`，可被 worker / 工具 / 测试直接调用）→ `models/*`。
采集器只负责“调用 HCS + 转成标准化数据”，不写库（容器事件、ECS 状态这类需要本地状态的除外，通过 `RunContext.db`）。

### 3.2 统一响应与错误

- 成功：`return ok(data)` → `{"code": 0, "message": "ok", "data": ...}`；分页数据 `{"items", "total", "page", "page_size"}`。
- 业务错误：`raise BizError(ErrorCode.BAD_REQUEST, "中文提示", 400)`；`not_found("巡检任务")`。错误码：`40001` 参数、`40101` 未登录、`40301` 无权限、`40401` 不存在、`40901` 冲突、`50001` 内部、`50201` HCS 上游。
- 参数校验失败统一返回 400 + `40001` + Pydantic 错误明细；未捕获异常返回 500 + `request_id`（日志里按它查）。
- 提示语面向运维人员：说清楚“哪里不对、怎么改”，例如“crontab 表达式不正确：…（格式：分 时 日 月 周）”。

### 3.3 权限与数据范围

```python
@router.put("/tasks/{code}", summary="修改任务：周期（秒）/ crontab / 启停")
def update_task(code: str, body: TaskPatch, db: Session = Depends(get_db),
                audit: Auditor = Depends(get_auditor),
                _: CurrentUser = Depends(require_perm("task:edit"))):
    ...
    audit.log("task.update", target_type="task", target_id=code, target_name=t.name, detail={"changes": diff})
    return ok(...)
```

- `require_perm("a", "b")` 需全部满足；`require_perm("a", "b", any_of=True)` 满足任一。
- 数据范围：`scope: Scope = Depends(get_scope)`，查询用 `scope.apply(select(...), Model.tenant_id, include_global=True)`；
  `scope.tenant_ids is None` 表示全部租户。前端顶部租户切换通过请求头 `X-Tenant-Id` 传入，与用户范围取交集。
- 写接口必须声明权限点（`tests/test_apidoc.py` 会检查）；公开接口只有登录、登录页选项、邮件快捷操作、SSE（凭票据）。
- 28 个权限点定义在 `app/core/permissions.py`（`PERMISSIONS`、`BUILTIN_ROLES`、`ADDED_IN`）。

### 3.4 审计

所有写操作调用 `audit.log(action, target_type=..., target_id=..., target_name=..., tenant_id=..., detail=...)`（默认随之提交事务）。
`action` 用“对象.动作”（如 `silence.create`、`collect.update`、`ledger.import`）；`detail` 放变更前后（`{"changes": {"字段": [旧, 新]}}`）。**口令、SK、Token 不得写入 detail。**

### 3.5 时间、配置、日志

- 时间：数据库列用 `UtcDateTime`，代码里用 `app.models.base.utcnow()`；对外 ISO 8601；按平台时区（`INSPECTOR_TIMEZONE`）计算的只有 crontab、静默循环窗口和报表周期。
- 配置：`get_settings()`（环境变量前缀 `INSPECTOR_`，见 `backend/.env.example`）。页面可改的配置走 `settings_service`（`sys_setting` 表），**不要**新增“改了要重启”的环境变量。
- 日志：`log = logging.getLogger(__name__)`；输出 JSON，可带 `extra={"task": ..., "project": ...}`；不要打印凭据和完整响应体。

### 3.6 调用 HCS

```python
ctx.client.get("dcs", "/v2/{project_id}/instances", params={"offset": 0, "limit": 100})
page_all(lambda p: ctx.client.get("dcs", "/v2/{project_id}/instances", params=p), "instances",
         limit=1000, total_key="instance_num")
```

- 第一个参数是服务名（对应 `INSPECTOR_HCS_ENDPOINTS` 的键），`{project_id}` 自动替换；客户端已处理认证、限流、401 刷新、429 / 5xx 重试。
- AOM 全局停用，所有资源（含 ECS）不调用。旧映射、端点、成功能力记录与历史样本均不能作为当前来源；新配置拒绝非 null AOM，`aom:null` 只清除旧值。DCS、GaussDB 走原生接口，ECS 可使用租户 Prometheus。`guarded_ces` 仅供旧部署显式兼容，AUTO 不探测 CES。详见 [AOM停用说明](AOM停用说明_20261102.md)。
- 只允许调用查询接口。新增接口时同步在 `app/tools/probe.py` 的 `PROBES` 里登记，联调时才能用 `make probe` 核对字段。

## 4 常见开发任务

### 4.1 新增一个巡检采集器

1. `app/collectors/<服务>.py` 新建类：`code`（任务代码）、`service`、`name`，实现 `collect(ctx: RunContext) -> list[Observation]`。
   每个 `Observation` = 资源类型 + 资源 ID + 名称 + 检查项 `check_item` + `facts`（规则表达式使用的扁平字段），可带 `status_raw` / `attrs` / `metrics` 回写资源表。
2. 在 `app/collectors/registry.py` 的 `TASKS` 中注册。
3. 在 `app/services/catalog.py` 登记（**唯一来源**，其余清单自动派生）：资源类型不存在时加入 `RESOURCE_TYPES`（`service`、`name`、`category`、`ledger`、`group`、`tag`、`columns`）；在 `TASK_SPECS` 加一条 `TaskSpec`（代码、名称、服务、默认周期、采集的资源类型 `types`、负责的检查项 `checks`、说明 `note`）。采集开关映射、内置任务初始化（`bootstrap`，已部署环境升级时自动补齐且不覆盖已有任务）、巡检证据归属、资源指南中的“巡检任务”、任务页说明都由它派生；`collectors/registry.py` 在导入时校验采集器与 `TASK_SPECS` 一致。
4. 前端：`utils/dict.ts` 的名称字典同步新类型；作业类 / 只巡检类型放入 `JOB_TYPES` / `INSPECT_ONLY_TYPES`。
5. 在 `app/rules/default_rules.yaml` 中增加规则（见 4.3）；资源 / 指标 / 事实说明写在 `services/resource_guides.py`，再执行 `make guides` 重新生成 `docs/资源与指标指南.md`（`tests/test_resource_guides.py` 逐字校验）。
6. Mock HCS（`mock_hcs/app.py` + `inventory*.py`）增加对应接口和两个租户的数据；`tools/probe.py` 登记接口并在 `TYPES` 写明对应资源类型。
7. 测试：先跑 `tests/test_catalog_consistency.py` 确认各处一致；再参考 `tests/test_pipeline.py`，用 `world` + `mock_http` 夹具跑一次 `run_task`，断言资源、告警、恢复。

```python
class DcsCollector:
    code, service, name = "dcs_status", "dcs", "DCS 实例状态与内存"

    def collect(self, ctx: RunContext) -> list[Observation]:
        insts = list(page_all(lambda p: ctx.client.get("dcs", "/v2/{project_id}/instances", params=p),
                              "instances", limit=1000, total_key="instance_num"))
        obs = []
        for i in insts:
            obs.append(Observation("dcs_instance", i["instance_id"], i["name"], "instance_status",
                                   {"status": i.get("status")}, status_raw=i.get("status")))
        return obs
```

### 4.2 新增一个台账资源类型

1. `app/ledger/fetchers.py` 写 `fetch_xxx(c: HcsClient, ctx: dict) -> list[LedgerRecord]`（`resource_id`、`name`、`status`、`az`、`ip`、`spec`、`vcpus`、`memory_gb`、`storage_gb`、`created_time`、`attrs`），注册到 `FETCHERS`（导入时校验与 `catalog.LEDGER_TYPES` 完全一致）。
2. `catalog.RESOURCE_TYPES` 增加类型并设 `"ledger": True`、分类、列表特有列（`columns`，取 `attrs.xxx` / `metrics.xxx`）；资源指南 `resource_guides.py` 需有对应条目。
3. 比对时哪些字段变化算“变更”在 `ledger/sync.py` 中维护；释放保护（拉取失败跳过、`EMPTY_GUARD`）自动生效。
4. Mock、probe、测试（`tests/test_ledger.py`）同步补齐；前端台账页列配置在 `views/ledger/columns.ts`。

### 4.3 新增 / 修改内置规则

```yaml
- id: R-DCS-005                     # 唯一，前缀按服务
  name: DCS 内存使用率过高
  resource_type: dcs_instance
  check_item: memory                # 与采集器 Observation.check_item 对应
  kind: threshold                   # threshold：多级阈值；state：条件表达式（expr.when）
  expr:
    value: memory_usage             # facts 里的字段或表达式
    unit: "%"
    title: "内存使用率 {value}（{threshold}）"
    levels: [{severity: P1, op: ">=", threshold: 95}, {severity: P2, op: ">=", threshold: 90},
             {severity: P3, op: ">=", threshold: 80}]
  for_count: 3                      # 连续命中 3 次才触发
  recover: {below: 75}              # 回差：低于 75 % 才恢复（state 规则用 {when: "status == 'RUNNING'"}）
  repeat_interval_sec: 3600         # 持续告警的重复提醒间隔
  runbook: |                        # 处置建议，显示在告警详情和邮件里
    1. 使用 DCS 控制台“缓存分析 - 大 Key 分析”定位大 Key ……
```

- 表达式是安全子集（比较、`and` / `or` / `not`、算术、`in`、`abs` / `min` / `max` / `len` / `round`、三元表达式），引用不存在的字段视为“无数据”，保持现状。
- `default_rules.yaml` 只在规则**不存在**时写入（以及给没有处置建议的规则补上 runbook）；已部署环境要改阈值请在“规则管理”页面改，或写迁移脚本。
- 规则测试：`tests/test_rules.py`（纯函数，最快）。

1. 在对应 `api/v1/<模块>.py` 加路由：`summary` 写清用途（会进入接口清单）；声明 `require_perm`；写操作调用 `audit.log`；按需 `get_scope`。
2. 请求 / 响应模型放 `schemas/`；字段校验写在 Pydantic 里，错误提示用中文。

4. `make apidoc` 重新生成 `docs/接口清单.md`，`make test`（`test_apidoc` 检查权限声明）。
5. 前端在 `src/api/index.ts` 增加调用、`src/types/index.ts` 增加类型。

### 4.5 新增页面

1. `src/views/<模块>/XxxView.vue`；页头用 `PageHeader`，表格分页用 `useTable`，状态 / 级别标签用 `StatusTag` / `SeverityTag`，文案字典放 `utils/dict.ts`，时间格式化用 `utils/format.ts`。

### 4.6 新增系统设置项

读取时缺失字段自动补默认值，**新增字段不需要迁移**；页面通过 `GET/PUT /system/settings/{key}` 读写（带审计）。

### 4.7 新增权限点

1. `app/core/permissions.py` 的 `PERMISSIONS` 增加（`模块:动作`、中文名、分组），按需加入内置角色。
2. 已部署环境：在 `ADDED_IN["x.y.z"]` 中登记要自动补给的内置角色，并在该版本迁移脚本中调用补授逻辑（参考 `0003` 的 `_grant_new_permissions`）。
3. 前端权限点名称取自接口（角色页自动显示），按钮加 `v-perm`；重新生成接口清单。

### 4.8 数据库迁移

```bash
make revision m="add xxx"       # autogenerate，生成后务必人工检查
make migrate                    # 本地升级（SQLite）
```

- **向前兼容**：只加表 / 加可空列 / 加索引；删列、改类型分两个版本做（先停用、下个版本再删）。升级流程是“新版本先迁移、旧进程仍在运行”。
- SQLite 改表用 `op.batch_alter_table`；JSON 列用 `sa.JSON().with_variant(postgresql.JSONB(), "postgresql")`；时间列用 `app.core.db.UtcDateTime`。
- 数据补齐（如给内置角色补权限）写在迁移里，保证幂等。
- `tests/test_migrations.py` 会在空库上从 0001 升级到 head 并与模型比对；发版前在 PostgreSQL 上执行一次 `alembic upgrade head`。

## 6 前端约定

- 接口统一走 `src/api/request.ts` 的 axios 实例（`src/api/index.ts` 按模块封装）：自动带 `Authorization` 与 `X-Tenant-Id`（顶部租户切换），解包 `data`，出错弹出后端 `message`（`silent` 可关闭）；401 清除登录跳转登录页。
- 状态：`stores/user.ts`（登录信息、权限点 `can` / `canAny`、租户范围）、`stores/app.ts`（当前租户、侧栏等）。
- 实时：`composables/useAlarmStream.ts`（换票据 → EventSource → 断线指数退避重连：5 / 10 / 20 / 40 / 60 秒）。
- 表格页：分页用 `useTable`；可从邮件 / 总览跳转的页面支持 URL query 预置筛选或打开详情（如告警中心 `?id=`）。

## 9 常见问题

- **改了规则 YAML 没生效**：已存在的规则不会被覆盖，到“规则管理”页面修改。
- **新任务没出现在巡检任务页**：执行 `make bootstrap`（生产在 `make migrate` 中自动执行）。
- **页面改了任务周期多久生效**：调度进程每 30 秒同步一次配置。
- **本地没有 Redis**：可以不配；多进程场景（API 多 worker + 调度 + 通知）要配 Redis，SSE 才能收到其他进程产生的告警。
- **mypy 报 SQLAlchemy 类型**：使用 `Mapped[...]` 声明，查询结果用 `db.scalar(...)` / `db.scalars(...)`。
